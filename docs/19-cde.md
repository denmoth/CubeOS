## Шаг 1: как устроено

```
приложение (процесс ядра)          оконный менеджер cde.wm (процесс сессии, держит фокус ввода ядра)
  win = cde.app.open(sys, ctx, ..)   ── окно: общий объект в памяти ──>   список окон (z-порядок), фокус, мышь, клавиши
  рисует в win.canvas / win.cells                                         cde.compositor: обои + окна по изменённым местам
  win:present() ── cubeos_cde (sys.post) ──>  менеджер забирает изменённую область canvas
  win:wait_event() <── key, char, mouse_*, win_* (sys.post, координаты окна) ──
```

- **Окно это объект `cde.window`**, общий для приложения и менеджера (все процессы в одной Lua-машине, поэтому картинка не пересылается). Пиксельное окно: `win.canvas` (поверхность `cgl`). Текстовое: `win.cells` (`ui.cells`, цвета CC 0..15) рисуется шрифтом Monocraft 6x9 в тот же canvas при `win:present()`, курсор мигает, пока окно в фокусе.
- **Ввод.** Все события CC получает менеджер (фокус ядра у него). Сочетания он обрабатывает сам, остальное передаёт окну в фокусе (мышь окну под курсором) новым вызовом ядра `sys.post` в координатах окна; последний аргумент номер окна. Окно будит менеджер тем же `sys.post` событием `cubeos_cde` (потомок предку можно только `cubeos_*`).
- **Сборка кадра** (`cde.compositor`): список изменённых прямоугольников, близкие сливаются; для каждого ищется верхнее окно, которое закрывает его целиком (тогда нижние слои не рисуются), иначе обои; поверх окна снизу вверх: тень (затемнение таблицей `theme.dim_map`), заголовок, содержимое, рамка со скруглёнными углами. Потом `cgl` сравнивает кадр только в изменённой области. Один символ в текстовом окне пересобирает одну клетку (это проверяет тест).
- **Палитра одна на экран** (`cde.theme`): 0..15 цвета CC в тонах темы, 16..231 куб 6x6x6, 232..255 цвета интерфейса (обои, рамки, заголовки). Приложения берут цвета через `cde.app.rgb` и `cde.app.ramp` (ближайшие по всей палитре) или роли темы (`app.theme.WIN_BG`, `TITLE_TEXT`). Темы шага 1: `tokyo-night` (по умолчанию), `dark`, `light`; файлами их сделает cdk (шаг 2). Тёмных тонов в кубе мало (уровни 0, 95, 135...): на шаге 2 решить, отдавать ли часть палитры под плавные тёмные ступени.
- **Процессы приложений** запускает `wm:launch(program, {name}, args)`: дочерние процессы менеджера; обёртка ловит ошибку и закрывает окна упавшего приложения (`wm.exits`), раз в секунду менеджер сверяет окна со списком процессов (убитые снаружи).

## Шаг 2.1: темы файлами и вид окон (2026-10-16)

- **Тема это файл** `assets/themes/<имя>.theme` (JSON5, свои кладутся туда же или в папки `theme_dirs` менеджера; поля, которых нет в файле, берутся из встроенной Tokyo Night). Готовые: `tokyo-night` (по умолчанию: значки справа, градиент в заголовке, углы 2), `dark` (в духе KDE: «закрыть» в круге, стрелки, заголовок по центру, углы 3), `light` (в духе Mac: цветные кружки слева, порядок закрыть/свернуть/развернуть, по центру, углы 4), `nord` (кружки справа, без рамки, углы 3).
- **Поля:** `text` (16 цветов CC), `desk` (ступени обоев), `title_active` (цвет или список цветов: градиент слева направо), роли (`win_bg`, `title_inactive`, `title_text`, `title_dim`, `border_active`, `border_inactive`, `close`, `button_down`, `accent`, `preview`, `desk_line`, `desk_glow`, `btn_close`, `btn_min`, `btn_max`) и `window`: `buttons` (`left`/`right`), `order`, `style` (`win`, `mac`, `kde`), `radius` (0..4), `border` (true/false), `title_height`, `title_align` (`left`/`center`), `shadow` (0..3), `shadow_strength`.
- **Палитра** (`cde.theme`): 0..15 цвета CC темы, 16..215 куб, 216..223 обои, 224..231 градиент заголовка, 232..247 роли, 248..255 запас (анимации палитрой, шаг 2.5).
- **Заголовок** собирается в отдельную картинку и пересчитывается только при изменении (фокус, название, нажатая кнопка, размер, тема), поэтому градиент с узором Байера ничего не стоит при перерисовке. Скругление делается отсечением строк углов, там видно то, что под окном; тень повторяет скругление.
- **Смена темы на ходу:** `wm:set_theme(имя)` (пока сочетание Ctrl+Alt+T, потом «Настройки»): палитра (обои и всё, что нарисовано цветами темы, меняются без перерисовки), рамки по новой теме, размер содержимого окон сохраняется, окна получают `win_theme`.
- **F11:** полный экран без рамки (`state = "full"`), повторно обратно к прежнему состоянию; окна постоянного размера тоже можно.
- **Свой заголовок приложения:** `{decorations: false}` (рамки и заголовка менеджера нет, содержимое с края окна), `win:set_drag_areas([[x, y, w, h]])` за эти места окно таскают и разворачивают двойным кликом, `win:request("min" | "max" | "full" | "normal")` кнопки приложения; края для размера, тень и скругление остаются у менеджера. Пример: «Mini player» в демо.
- **Расстановка новых окон** как «умная» в KDE: из точек сетки берётся та, где окно меньше всего закрывает видимые окна, при равенстве ближе к центру.
- Тесты: `lib_cde_theme` (файлы тем, порядок и сторона кнопок, скругление, свой заголовок, F11, смена темы), `lib_cde_wm`, `lib_cde_session`.

## Мышь и клавиши (шаг 1)

| Действие | Как |
|---|---|
| Поднять окно, фокус | клик в любом месте окна |
| Переместить | тянуть заголовок; у верхнего края экрана рамка предпросмотра «на весь экран», у левого и правого «половинка», отпустить там |
| Развернуть, вернуть | двойной клик по заголовку, кнопка □, Alt+↑ / Alt+↓ |
| Половинки | Alt+Shift+← / → (повторно вернуть), перетаскивание к краю |
| Свернуть | кнопка _, Alt+↓ в обычном состоянии; вернуть Alt+←/→ |
| Размер | тянуть края и углы (полоса 2 пикселя), текстовое окно меняется целыми клетками |
| Предыдущее / следующее окно | Alt+← / Alt+→ (по порядку открытия) |
| Закрыть | кнопка ×, Ctrl+T (окно получает `win_close`), удержание Ctrl+T убивает приложение |
| Рабочий стол | Alt+D (повторно вернуть окна) |
| Полный экран | F11 (повторно вернуть) |
| Следующая тема | Ctrl+Alt+T (пока нет «Настроек») |
| «Пуск» | одиночное нажатие левого Alt вызывает `wm.on_start` (меню на шаге 3) |
| Свои сочетания | `wm:hotkey("alt+enter", fn)` |

Развёрнутое или прилипшее окно, которое тянут за заголовок, возвращается к прежнему размеру под мышью. Окно с `resizable: false` не разворачивается и не прилипает. Наведения мыши в CC нет (только нажатия и перетаскивание), поэтому кнопки подсвечиваются только при нажатии.

## API окна для приложений

```cubic
import cde
def main(sys, ctx):                                     # ctx от wm:launch: ctx.wm, ctx.args
    win = cde.app.open(sys, ctx, {title: "Hello", kind: "text", cols: 30, rows: 8})
    win:text(1, 1, "Привет", 0, 15)                      # цвета CC: 0 белый ... 15 чёрный
    win:present()
    while true:
        ev = table.pack(win:wait_event(0.5))            # nil по таймауту
        if ev[1] == "win_close":
            break
    win:close()
```

События окна: `key(код, held, id)`, `key_up(код, id)`, `char(символ, id)`, `paste(текст, id)`, `mouse_click/mouse_drag/mouse_up(кнопка, x, y, id)`, `mouse_scroll(направление, x, y, id)` (пиксельное окно: пиксели содержимого с нуля; текстовое: клетки с единицы, как в терминале CC), `win_resize(ширина, высота, id)` (`win.canvas` уже новая поверхность, нарисовать заново), `win_close(id)`, `win_focus(id)`, `win_blur(id)`. Параметры окна: `title`, `kind` (`pixel`/`text`), `w`, `h` или `cols`, `rows`, `x`, `y` (иначе лесенкой от центра), `resizable`, `min_w`/`min_h` или `min_cols`/`min_rows`, `bg`.
