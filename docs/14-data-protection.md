# 14. Защита данных и ресурсов (решено 2026-10-15)

Решения D194–D205 в [08-decisions-log.md](08-decisions-log.md). Это дополняет модель угроз из [12-permissions-capabilities.md](12-permissions-capabilities.md): там защита от не-админов внутри системы, здесь защита от того, кто **добрался до компьютера**: вошёл в CraftOS, унёс диск, скопировал мир или взломал администратора ресурса.

## Цели

1. **Читать и менять нельзя.** Кто попал в CraftOS (или унёс диск), не может прочитать и осмысленно изменить защищённые данные: они зашифрованы с проверкой подлинности, подделка и подмена файлов обнаруживаются.
2. **Разрушить можно, но потеря минимальна.** Удалить или испортить данные нельзя запретить (в шелле CC нет запретов), поэтому у каждого защищённого ресурса есть облачная (внешняя) резервная копия, из которой восстановление идёт с минимальными потерями.
3. **Второй фактор: дискета-аутентификатор**, плюс фраза восстановления и необязательные TOTP и внешнее подтверждение.
4. **Необязательно.** Всё включается профилем, по умолчанию выключено и ничего не стоит.

Честные пределы (пишем пользователю прямо): разблокированная, работающая машина в руках атакующего читается из памяти; код загрузки может подменить тот, у кого есть доступ к файлам мира и кто потом дождётся ввода пароля. Поэтому важные операции требуют второго подтверждения даже в открытой сессии (профиль «Охрана»).

## Профили

| Профиль | Что включено |
|---|---|
| Базовый (по умолчанию) | ничего лишнего, права CFS как есть |
| Приватный | шифруется домашняя папка пользователя, ключ из пароля |
| Хранилище | все пользовательские данные и данные приложений зашифрованы всегда, расшифровка только в памяти; автоблокировка по простою затирает ключ |
| Охрана | к Хранилищу добавляются подтверждение двумя, лимиты, отложенные операции, внешний журнал и резервирование; политика по ресурсам в JSON5 |

Выбор при установке или в настройках; для отдельных папок и ресурсов можно переопределить.

## Шифрование

- **Мастер-ключ** пользователя: случайные 256 бит. Лежит только в двух обёрнутых видах: ключ из пароля (PBKDF2-HMAC-SHA256, отдельная соль, не та, что у хэша входа) и ключ из фразы восстановления. Смена пароля перешифровывает только обёртку.
- **Файлы** шифруются по одному, лениво (при записи и чтении), потоковым шифром с проверкой подлинности (ChaCha20 + HMAC-SHA256, шифровать затем подписывать). В подпись входят путь, номер версии и идентификатор ресурса: файл нельзя подменить другим или откатить без обнаружения (для отката нужен внешний свидетель: цепочка хэшей в журнале и копия в чужом хранилище).
- **Ключ только в оперативной памяти.** Затирается при выходе, блокировке, простое, Ctrl+T, выключении. На диске только шифртекст.
- В зашифрованное идёт пользовательское (дом, токены, данные приложений). Система, программы и общие файлы нет. Временные файлы в памяти (`/cubeos/tmp`), секреты не попадают в логи.
- Загрузка не ждёт массовой расшифровки: на входе только вывод ключа (около секунды).

## Фраза восстановления

Любой длины: энтропия 128–256 бит кодируется словами из словаря 2048 слов (12, 24 слова или формат Monero 24+1 проверочное, словари на нескольких языках). Показывается один раз при создании пользователя с явным предупреждением: потеряны и пароль, и фраза, данные потеряны. Забыл пароль: фраза открывает вторую обёртку и задаётся новый пароль. Необязательный ключ восстановления администратора (escrow) для рабочих серверов.

## Дискета-аутентификатор

Ключ лежит файлом на дискете («YubiKey» внутри игры). Режимы: пароль + дискета; только дискета; дискета только как подтверждение опасных операций. Два варианта ключа: симметричный (обёртка мастер-ключа) и асимметричный (проверяющий хранит только публичный ключ, у него украсть нечего, закрытый ключ только на дискете). Дискета вынута: система заблокирована или просит ключ заново.

## Дополнительные факторы

- **TOTP** (Google Authenticator и совместимые): HMAC-SHA1 от `os.epoch("utc")`, QR рисуется в пиксельном терминале, запасной вариант ключ base32. Настоящая вторая ступень для сетевых сервисов (банк, магазин, админ-панель, сервер знает секрет). Для локального входа только дополнительный барьер, сам по себе ключ данных не открывает (секрет лежит на том же диске).
- **Внешнее подтверждение** без своих серверов: запрос «разрешить?» уходит в Telegram-бота или Discord, ответ с аккаунта админа. Работает там, где разрешён http.

## Защита администратора ресурса («Охрана»)

Один взломанный администратор не может нанести необратимый вред:
1. Роль оператора с ограниченными правами для повседневной работы; корневой ключ (фраза) отдельно и редко.
2. Опасные операции (вывод больших сумм, удаление, смена администратора) требуют подтверждения m из n ключей (дискета, телефон, второй администратор).
3. Крупные операции откладываются (по умолчанию на сутки), другой ключ может отменить.
4. Суточные лимиты; журнал только на дописывание с цепочкой хэшей; копия журнала во внешнее хранилище, которое админ не может переписать.
5. Автоблокировка и повторное подтверждение чувствительных действий даже в открытой сессии.

## Резервные копии

Служба резервирования: инкрементально, шифрование на клиенте (облако видит шифртекст), получатели на выбор: другой узел кластера, http-адрес пользователя, диск, стороннее хранилище (ключ доступа только на запись, чтобы удалить копию нельзя). Расписание и политика хранения в JSON5. Восстановление по фразе. Профиль настроек и список пакетов (dotfiles: JSON5 + манифест `stew`) переустанавливают систему и приложения одной командой; сами пакеты не копируются, их ставит `stew`.

## Внезапные отключения

- Атомарная запись: во временный файл, проверка, переименование; половинчатых файлов нет.
- Журнал операций (write-ahead log) для важного; после «грязного» выключения (отметка незавершённой загрузки уже есть, [boot.md](spec/boot.md)) журнал доигрывается или откатывается.
- Денежные и подобные операции это транзакции; журнал только дописывается, у записи хэш предыдущей; хвост проверяется при старте.

## Антивирус и кейлоггеры

Не сигнатурный сканер, а **служба аудита прав** (вместе с песочницей): ввод и так идёт только активной программе, программа без права «слушать все клавиши» кейлоггером быть не может. Служба следит, какие права просили и получили приложения, сверяет хэши пакетов с магазином, предупреждает о запросах «слушать всё» и «писать в startup». Исключения это выданные права. Простые эвристики по коду (`pullEventRaw`, запись в `startup`, http на чужие адреса) только подсказка.

## Загрузка и защита входа

- `startup` это одна строка: она находит и запускает загрузчик из системы. Загрузчик, экран загрузки и интерфейс задаёт DE (он обязателен, запасного загрузчика нет). Если загрузчик упал, запасной выход это **восстановление с паролем администратора**, а не голый CraftOS.
- Загрузка идёт столько, сколько нужно, с экраном и полосой; окно клавиши (F2) в начале около секунды. Меню выбора (как dual boot: CubeOS, безопасный, восстановление, CraftOS) включается в настройках.
- Система с первого такта ловит `terminate` через `pullEventRaw` и не отдаёт управление CraftOS; вход в CraftOS только через меню с паролем администратора. Выключение питания возвращает в загрузчик.
- Время: служба времени (часовой пояс или игровое время, секунды по настройке), см. D204.
