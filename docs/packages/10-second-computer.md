# Второй компьютер как хранилище пакетов (шаг 8)

Идея расширителя (docs/21-axo.md, D261), доведённая до пакетов: система влезает на компьютер с 1 МБ диска, потому что то, что не
влезло (сначала `optional`, потом `recommended`), лежит на другом компьютере ComputerCraft, соединённом модемом (проводным или
беспроводным). Модули таких пакетов читаются по сети в момент импорта. `stew` ведёт их как обычные пакеты.

Файлы: `game/pkghost.lua` (программа второго компьютера), `lib/stew/remote.cub` (клиент), правки `lib/stew/{init,txn,db}.cub`,
`sys/boot/pkgload.lua`, `lib/cpk.cub` (`open_src`), `lib/cush/stewcmd.cub`, `lib/setup/*` (экран «не влезает»).
Тест: `tests/cases/lib_stew_remote.cub`.

## Как пользоваться

1. На втором компьютере (обычный CraftOS, CubeOS не нужен): `wget run <url>/pkghost.lua` или скопировать файл дискетой и запустить.
   Первый запуск предлагает создать `/startup.lua`. Экран показывает код сопряжения (6 цифр), номер компьютера, свободное место,
   список пакетов и последние события. `R` меняет код, `Q` выходит. Пакеты лежат в `/cubeos-host/`.
2. Соединить оба компьютера модемами (проводной модем + кабель, или два беспроводных).
3. На компьютере с CubeOS: `stew host pair 482913` (или в установщике: «Second computer for optional packages»).
4. Дальше `stew install ...` сам переносит пакеты на второй компьютер, если не влезает; вручную: `stew storage ID remote [HOST]`,
   обратно `stew storage ID packed`.

Команды: `stew host pair CODE [HOST]`, `stew host list`, `stew host info ID` (место и файлы), `stew host clean ID` (убрать файлы,
которых нет ни в одном пакете), `stew host forget ID [--force]`.

## Протокол (канал 4277)

Сообщение это таблица Lua, `modem.transmit(4277, ответный_канал, msg)`; ответный канал клиента `20000 + id % 20000`. Хост слушает
канал 4277 на всех подключённых модемах и отвечает на том, откуда пришло. Поля общие: `p = "cpkhost"`, `v = 1`, `op`, `cid`
(номер клиента), `hid` (номер хоста).

Подпись: `mac = hex(HMAC-SHA256(K, canon(сообщение без mac)))`. `canon` это однозначная запись: строка `s<длина>:<текст>`, число
`#<целое>;`, булево `T`/`F`, таблица `{` + пары (ключи по порядку) + `}`. Одна и та же в `pkghost.lua` и `remote.cub`.

### Сопряжение (код не уходит в эфир)

1. Клиент -> всем (или хосту `hid`): `hello {cid, cn}`; `cn` случайный nonce клиента.
2. Хост -> клиенту: `hello_ok {cid, hid, re = cn, hn, label}`; `hn` nonce хоста.
3. Обе стороны считают `pk = HMAC(код, "cpkhost-pair" .. cn .. hn)`.
4. Клиент -> хосту: `pair {cid, hid, cn, hn, proof}`, `proof = HMAC(pk, "C" .. cn .. hn .. cid .. hid)`.
5. Хост проверяет. Неверно: `denied {err = "wrong code"}`, три ошибки подряд меняют код. Верно: ключ `K = HMAC(pk, "K" .. cn .. hn)` (на
   обеих сторонах, по сети не идёт), клиент запомнен, код меняется, ответ `pair_ok {proof = HMAC(pk, "H" .. cn .. hn .. cid .. hid), label, free}`.
6. Клиент проверяет `proof` хоста (хост доказал, что знает код) и сохраняет `{id, key, label}`.

Код действует 10 минут и до первого успешного сопряжения. Хост помнит до 8 незавершённых `hello`. Несколько клиентов можно
сопрячь с одним хостом, у каждого свой ключ; хост хранит их в `/cubeos-host/.clients`.

### Запросы после сопряжения

Запрос: `{op, cid, hid, n, ...поля, mac}`; `n` растёт строго (миллисекунды UTC, но не меньше предыдущего + 1). Хост отвечает
только если подпись верна, `n` больше последнего принятого от этого клиента и отличается от его часов не больше чем на 2 минуты.
Повтор запроса с тем же `n` (потерялся ответ) возвращает тот же ответ, а не выполняет операцию второй раз; более старый `n`:
`stale request`, а неверная подпись молча отбрасывается.
Ответ: `{op = "res", cid, hid, re = n, ok, err, ...поля, mac}`. Клиент принимает ответ только с `re` своего запроса и верной
подписью; поддельный ответ игнорируется (если верного нет, ошибка «ответ не прошёл проверку подписи»).

| op | Поля запроса | Ответ |
|---|---|---|
| `info` | нет | `free`, `cap`, `label`, `files = {имя: размер}` |
| `put` | `name`, `offset`, `data` (до 16 КБ, клиент шлёт по 8 КБ), `total`, `last`, при `last` ещё `sha` | `ok`. На `offset = 0` хост проверяет место (запас 4 КБ) и начинает `<имя>.part`; куски строго подряд; на `last` проверяет размер и sha256 всего файла и только тогда переименовывает |
| `read` | `name`, `offset`, `length` (до 16 КБ) | `data`, `size` |
| `delete` | `name` | `ok` (убирает и недописанный `.part`) |
| `forget` | нет | `ok`, хост забывает клиента |

Имя файла: буквы, цифры, `. _ @ -`, до 80 знаков, без `..` и не с точки. Остановка посреди `put` оставляет `.part`, который хост
стирает при следующем запуске.

### Что защищено и что нет

Защищены подлинность и целостность: подделать, изменить, подменить или повторить запрос и ответ нельзя без ключа; файл при записи
проверен sha256 целиком. **Секретности нет**: пакеты идут открыто (это код, а не пароли). Ключ `K` защищён только тем, что его
не видели в эфире. Предел защиты сопряжения: 6 цифр. Тот, кто записал обмен при сопряжении, может потом перебрать 10^6 кодов
у себя и получить `K`; поэтому сопрягайте, пока рядом нет чужих (проводной модем безопаснее беспроводного), а при подозрении
`stew host forget` и сопрягите заново. Онлайн-подбор ограничен тремя попытками на код.

## Хранение в stew

Запись в базе `installed.json5`: `storage = "remote"`, `host` (номер), `rname` (имя файла на хосте: `<id>-<версия>.<txn>.cpk`,
уникально, чтобы откат не терял старый файл), `rsize`. В `size` только то, что осталось здесь (ресурсы системных пакетов).
`boot.idx`: `packages[id] = { remote = { host = 7, name = "...", size = N } }` и раздел `hosts = { [7] = { key = "..." } }` только
для хостов, где что-то лежит. Ключи хостов в `/cubeos/var/stew/hosts.json5`. Папка `/cubeos/var/**` по правилам CFS
(`lib/cfs/defaults.cub`) доступна только системе и администратору, обычным пользователям нет. Это же защита ключа; от
администратора и от того, кто унёс диск, ключ не защищён (docs/14-data-protection.md: защищённое хранилище ключей это отдельная задача).

**План** (`s:plan`): если после сжатия не влезает и есть сопряжённый хост (или `req.remote = номер`), пакеты переносятся на него:
сначала `optional`, потом `recommended`, большие первыми, пока не влезет и пока хватает места на хосте. Никогда: `essential`,
загрузочный набор (`BOOT_SET`), `cubeos.stew` и всё, от чего они зависят. План показывает у шага `storage = "remote"`, `host`, а в
`p.remote = {host, label, free, left, count, bytes}` итог по хосту. Пик места считается так: скачанное для хоста уходит и стирается
по одному, поэтому в пике только самый большой пакет для хоста. Уже стоящий на хосте пакет при обновлении остаётся там.

**Транзакция** (`txn`): пакеты для хоста скачиваются первыми; каждый сразу проверяется, отправляется на хост (в журнал заранее
пишется `remote`: хост + имя), читается обратно по сети через `cpk.open_src(reader)` (список модулей, установщик, ресурсы
системных пакетов), промежуточный файл стирается. Любая ошибка (хост пропал, повреждённый локальный пакет): откат удаляет
загруженное на хосте. Хост недоступен при откате: файл остаётся сиротой, его убирает `stew host clean`. Удаление и замена
удаляют старый файл хоста только после фиксации.

`s:set_storage(id, "remote"|"packed"|"unpacked", host)`: новая копия делается раньше, потом переключаются база и `boot.idx`, потом
старая удаляется. `s:verify(id)` читает пакет с хоста целиком и проверяет sha256 и блоки. `s:host_pair/host_forget/host_info/host_clean`.

## Чтение при работе системы

`pkgload.lua`: для `remote` пакета создаётся `cpk.Archive` поверх `src = {size, read(offset, length)}` из
`remote.Client:reader(...)`. Заголовок читается с упреждением 4 КБ (один запрос), блоки по 12 КБ; распакованные блоки кэширует
общий кэш `cpk` в памяти (256 КБ, на диск ничего не пишется). Модуль пакета загружается только при `import`. Нет ответа
(таймаут 3 с, 3 попытки): ошибка `the second computer #7 does not answer: package demo.opt2`.

### Как ждёт ответа модема

Сообщение приходит как событие `modem_message`. Ядро рассылает его всем процессам, которые ждут `modem_message` (в том числе
краткое ожидание `keep`, где остальные события процесса не теряются). Поэтому `remote.pull_modem(timeout)` работает в двух мирах:

- **до ядра и в чистом CraftOS** (загрузка до ядра, установщик): `os.pullEventRaw()` с таймером; события, пришедшие за это время
  и не относящиеся к нам, ставятся обратно по порядку (`os.queueEvent`).
- **внутри процесса ядра** (приложение, которое импортирует модуль позже; cush): тот же системный вызов, что у `net.link`:
  `coroutine.yield({op = "wait_event", filter = {"modem_message"}, timeout_ms, keep = true, net = true})`. Классическую программу
  (cush) его пропускает к ядру `compat.proc`.

Различает их глобальная переменная `__cubeos_boot_co`: `pkgload.new` при создании записывает в неё сопрограмму загрузки; если
сейчас работает другая сопрограмма, это процесс ядра. Все запросы клиент шлёт и ждёт через внедряемый транспорт
(`ctx.modem {open, transmit}`, `ctx.wait(filter, seconds)`), поэтому тесты подставляют поддельный модем.

## Установщик

Экран «не влезает», пункт 4 «Second computer for optional packages» (оба вида, текстовый и пиксельный): окно объясняет, что сделать,
принимает 6 цифр, сопрягает через `s:host_pair`, перепланирует с `remote`; сводка показывает, сколько пакетов и байт уйдёт на
второй компьютер, и предупреждение, что он должен быть включён. Установка идёт обычным `s:apply`; стадия прогресса `upload`.
`install.lua --text` и графика не затронуты (сеть только после ввода кода).

## Ограничения

- Скорость: каждый запрос и ответ подписываются sha256 на Lua, около 12 КБ на блок; чтение большого модуля с хоста заметно медленнее диска.
- Загрузка системы не должна зависеть от хоста: службы и модули в пакетах `essential` и загрузочном наборе остаются дома. Если пакет
  `recommended` (например часть рабочего стола) уехал на хост, а хост выключен, его модули не загрузятся и система скажет какой.
- Приложение «Магазин» показывает такой пакет как «распакован»; ресурсы вида `cpk:<id>:<путь>` на хосте читает только загрузчик.
- Один хост на несколько систем и несколько хостов на одну систему работают, но план выбирает первый сопряжённый.
