# Сборка пакета

## Кто собирает

- **`stew pack <папка>`** собирает `.cpk`. Работает без компилятора: пакеты на чистом Lua не требуют Cubic вообще.
- **Cubic подключается шагом сборки.** Если в пакете есть `.cub` (или `lang: "cubic"`), `stew pack` вызывает компилятор из пакета
  `cubeos.cubic`. Нет компилятора: понятная ошибка «нужен пакет cubeos.cubic», а не падение.
- `cubic pack` это просто короткое имя для `stew pack` в пакете компилятора (для привычки).
- Тот же код работает в трёх местах: в игре, в CraftOS-PC на ПК (так собирают тесты и GitHub Actions), в `tools/` репозитория
  (сборка всей системы для установщика).

## Что делает `stew pack`

1. Читает `package.json5`, проверяет поля (02-manifest.md).
2. Собирает список файлов по `files`.
3. `.cub`: выпускная сборка Cubic (`opts.release`, минификация) и карта строк. `.lua`: как есть или минификация (флаг `--minify`,
   по умолчанию включён для выпуска, выключен для `stew dev`). Синтаксис Lua проверяется `load` до упаковки.
4. Группирует модули в блоки (01-cpk-format.md), сжимает.
5. Считает `installed_size`, хэши файлов, sha256 архива.
6. Пишет `build/<id>-<version>.cpk` и `build/<id>-<version>.entry.json5` (готовая запись для каталога).

Флаги: `--no-maps`, `--method 0|1|2`, `--out <путь>`, `--check` (только проверить, не писать).

## Режим разработчика

- `cubic new app <имя>` (или `stew new app <имя>`): заготовка (манифест, `src/init.lua` или `init.cub`, иконка, README).
  Заготовки: `app`, `lib`, `service`, `theme`, `wallpaper`, `lang`.
- `stew dev <папка>`: подключить папку как установленный пакет без сборки. `.cub` компилируются при загрузке (нужен компилятор),
  `.lua` грузятся напрямую. `contributes` применяется как при установке. `stew dev --off <папка>` убирает.
- `stew try <пакет|файл.cpk|адрес>`: запуск без установки, в памяти и временной папке.

## Сборка всей системы

`tools/build_packages.lua` (новый, шаг 2a/2b) собирает все системные пакеты из 07-system-split.md в `build/packages/` и пишет
локальный `index.json5`. Тесты установщика и `stew` работают с этой папкой как с источником `path` без сети. Этот же инструмент
запускает GitHub Action в Cobble для системных пакетов.

## Воспроизводимость

Одинаковые исходники и одинаковая версия сборщика дают побайтно одинаковый `.cpk` (сортировка файлов, без времени сборки внутри).
Это нужно Cobble: сборка в Actions должна совпасть с тем, что автор проверил у себя.
