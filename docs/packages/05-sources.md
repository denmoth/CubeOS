# Источники пакетов

Общая часть (уровни доверия, подключение, разовая установка, подмена, хэши) в [spec/package-manager.md](../spec/package-manager.md).
Здесь устройство адаптеров и PineStore.

## Адаптер

Каждый вид источника (`kind`) это модуль `stew.source.<kind>` с одним интерфейсом:

| Функция | Что делает |
|---|---|
| `refresh(src, cache)` | скачать или обновить каталог, вернуть записи в общем формате (`index.json5` из package-manager.md) |
| `fetch(src, entry, version, dest)` | скачать пакет в staging, вернуть путь к `.cpk` (или собрать его, если источник даёт не `.cpk`) |
| `publish(src, pkg, auth)` | необязательно: отправить пакет (есть у `cobble`) |
| `search(src, query)` | необязательно: поиск на стороне источника; иначе stew ищет по кэшу каталога |

Ядро `stew` про виды источников ничего не знает: план, установка, откат одинаковы. Новый источник это новый адаптер.

## Виды в первой версии

| `kind` | Что | Доверие по умолчанию |
|---|---|---|
| `cobble` | официальный каталог (06-cobble.md): `index.json5` в репозитории, `.cpk` в GitHub Releases | `official` |
| `http` | любой адрес с `index.json5` в формате stew (свой каталог на GitHub, сайте, Gist) | `user` |
| `path` | папка: дискета, диск, расширитель, `build/packages` в тестах | `user` |
| `pinestore` | PineStore (ниже) | `community` |
| `pastebin` | разовая установка `stew install pastebin:<id>` | `adhoc` |
| `rednet` | соседний компьютер с кэшем пакетов (раздаёт по сети, без интернета) | `user` |

## PineStore

PineStore (pinestore.cc) это существующий каталог программ CC. API проверено 2026-10-18:

- `GET https://pinestore.cc/api/projects`: `{ success, projects: [...] }`, весь список одним ответом (~370 КБ JSON: на компьютере
  с 1 МБ кэшировать только нужные поля).
- Поля проекта: `id`, `name`, `description_short`, `description_markdown`, `install_command`, `download_url`, `target_file`,
  `run_command`, `repository`, `owner_name`, `tags`, `keywords`, `downloads`, `likes`, `date_publish`, `date_updated`,
  `has_thumbnail`, `visible`.
- **Версий нет.** Вместо версии берётся `date_updated` (или `date_publish`), версия для stew: `0.0.0+<дата>`.
- **Списка файлов и хэшей нет.** Есть `install_command` (`pastebin get|run <id>`, `wget <url> [файл]`, `wget run <url>`) и иногда
  `download_url` с `target_file`.
- Остальные адреса (`/api/project/<id>`, картинки, счётчик скачиваний, поиск) **проверить** на шаге 5b.

### Как адаптер ставит пакет PineStore

1. `refresh`: список проектов переводится в записи stew: `id` = `pinestore.<id>`, имя, описание, категория по `tags`,
   `kind: "legacy"`, размер неизвестен (план показывает «размер узнается при скачивании»).
2. `fetch`:
   - есть `download_url`: скачать файл, положить как `target_file`;
   - `pastebin get <id> <файл>` или `wget <url> <файл>`: скачать этот файл;
   - `pastebin run` / `wget run` (установщик-скрипт): запустить его **в песочнице** `compat` с виртуальной файловой системой
     (папка пакета как корень, сеть разрешена, остальное нельзя) и забрать всё, что он записал.
   Из результата stew сам собирает `.cpk` с манифестом `kind: "legacy"`, хэши считаются при скачивании и запоминаются: обновление
   с другим содержимым показывается как изменение.
3. Установленный пакет PineStore это программа CraftOS: запуск через `compat` в окне терминала CDE, с разрешениями уровня
   `community` (своя папка, сеть по запросу, без системных прав). В магазине помечается «программа CraftOS из PineStore».

Публиковать в PineStore из CubeOS не нужно (у них своя загрузка через сайт).

## Порядок источников и одинаковые имена

Порядок в `sources.json5` задаёт приоритет при поиске. Пакет привязан к источнику, из которого поставлен, и обновляется только из
него. Пакеты PineStore живут в своём пространстве `pinestore.*` и с пакетами Cobble не пересекаются.
