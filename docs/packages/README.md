## Решения владельца (2026-10-18)

1. **Ставим с интернета**, дискета потом. Сначала один компьютер. Потом предложение подключить второй компьютер (расширитель
   хранилища, docs/21-axo.md, D261) для менее важных пакетов, чтобы система влезала на компьютер с 1 МБ на чужом сервере.
2. **На компьютер идёт только готовый код.** Никаких `.cub` в установленной системе: пакеты дособраны (выпускной минифицированный Lua).
   Компилятор Cubic это отдельный необязательный пакет.
3. **Приложения можно писать на обычном Lua.** Cubic не обязателен ни для приложений, ни для сборки пакетов. Пакет на Lua собирается и
   ставится без компилятора.
4. **Вся система разбита на тонну мелких пакетов**, а не на 5-6 крупных (07-system-split.md).
5. **Каталог называется Cobble.** Отдельный репозиторий на GitHub (06-cobble.md).
6. **PineStore поддерживается сразу**, вторым источником. Менеджер с самого начала устроен под много видов источников (05-sources.md).
7. **Публикация прямо из игры делается сразу**, а не «потом» (06-cobble.md, через Worker).
8. **У пакетов бывают установщики**: опции, шаги, перенос настроек (04-installers.md).
9. **При настройке системы** выбираются пакеты и способ хранения (сжато / распаковано / авто) (08-setup-and-store.md).
10. **Название магазина не решено.** Владелец предложил CobbleStore и попросил подумать (варианты в 08-setup-and-store.md).
11. **Новых приложений сейчас не делаем.** Список будущих пакетов записан (07-system-split.md, раздел «Потом»), но сначала основа и
    проверка того, что уже есть.
12. **Субагентов использовать, одновременно сколько угодно.** Модель для сложного: Opus с effort high (не max). Механику можно Sonnet.

## Порядок работы

Каждый шаг: сложность, важность, модель. Шаги в одной строке «параллельно» можно отдать разным субагентам одновременно.

| # | Шаг | Сложность | Важность | Модель | Зависит от |
|---|---|---|---|---|---|
| 0 | Замеры: минимальный размер файла в CC (кажется, 500 байт), сжатие по файлам / группам / целиком на реальном `lib`, скорость распаковки нашим `deflate` в CraftOS-PC | средняя | высокая | Opus high | - |
| 1 | Утвердить формат `.cpk` v1 и `package.json5` по замерам (обновить 01, 02) | средняя | очень высокая | Opus high | 0 |
| 2a | Писатель и читатель `.cpk` (`lib/cpk/`), `stew pack` для Lua, шаг сборки Cubic | высокая | очень высокая | Opus high | 1 |
| 2b | Граф импортов `lib` (инструмент) и разметка всей системы на пакеты с манифестами | средняя | высокая | Sonnet | 1 (параллельно с 2a) |
| 2c | Репозиторий Cobble: раскладка, индекс, GitHub Action сборки | средняя | высокая | Sonnet | 1 (параллельно с 2a) |
| 3 | Загрузка модулей из `.cpk` (CFS монтирует архив, загрузчик берёт готовый Lua), карты строк в ошибках | высокая | очень высокая | Opus high | 2a |
| 4 | `stew` ядро: база установленных, план, установка целиком из файла и папки, удаление, откат, установщики пакетов | высокая | очень высокая | Opus high | 2a, 3 |
| 5a | Источники: Cobble (github/http), путь, кэш каталога | средняя | высокая | Opus high | 4 |
| 5b | Адаптер PineStore | средняя | средняя | Sonnet | 4 (параллельно с 5a) |
| 5c | Worker публикации и `stew publish` | средняя | средняя | Opus high | 2c, 4 |
| 6 | Установщик системы на чистый CraftOS: загрузчик одной командой, экраны, профили, способ хранения | высокая | очень высокая | Opus high | 5a |
| 7 | Магазин (приложение CDE) | средняя | высокая | Opus high (визуал должен впечатлять) | 5a |
| 8 | Второй компьютер для `optional` пакетов при нехватке места | высокая | средняя | Opus high | 6 |
| 9 | Проверка в игре всего, начиная с CDE шага 3 | - | очень высокая | владелец + Opus | 6 |

После каждого шага: тесты этого шага (`bash tools/test.sh <фильтр>`), полный прогон только перед коммитом крупного шага. Коммит
заканчивается строкой `Co-Authored-By` текущей модели. Решения записываются в docs/08-decisions-log.md (следующий номер D265).

## Чего не делать

- Не писать новых приложений и не добавлять «на всякий случай» видов пакетов, источников или опций сверх этих документов.
- Не класть в репозиторий личные обои владельца (они лежат в `CubeOS-userdata`, вне репозитория).
- Не хранить токен GitHub на компьютере в игре в открытом виде (06-cobble.md).
- Не переписывать готовые части (CFS, расширитель, CDE), а дописывать к ним.
