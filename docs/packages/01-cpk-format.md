# Формат `.cpk` версии 1

Дополняет раздел `.cpk` в [03-file-formats.md](../03-file-formats.md). Где здесь сказано иначе, верно здесь.

## Зачем один файл на пакет

- CC считает каждый файл как минимум за некоторый размер (в CC:Tweaked, по памяти, `MINIMUM_FILE_SIZE = 500` байт; **проверить** в
  исходниках и замером на шаге 0). В системе около 190 модулей, многие меньше 2 КБ: россыпь файлов съедает десятки КБ.
- Обновление пакета это замена одного файла, откат это возврат старого.
- Целостность проверяется одним хэшем.

## Раскладка

```
"CPK" 0x01                    сигнатура и версия формата (4 байта)
u32 длина манифеста
манифест                      JSON5 без сжатия: читается без распаковки (магазин, stew info, план)
u16 число блоков
таблица блоков                для каждого: смещение, хранимый размер, исходный размер, метод, CRC32
u16 число файлов
таблица файлов                для каждого: путь, номер блока, смещение внутри блока, размер, флаги (lua, карта, ресурс)
данные блоков
раздел карт строк             необязательный (флаг в заголовке), сжат одним блоком
sha256 всего, что выше         32 байта
зарезервировано под подпись    u16 длина + данные (в v1 длина 0)
```

Числа little-endian. Пути внутри пакета относительные, через `/`, без `..`.

## Блоки: сжатие по группам

Файл лежит внутри **блока**, блок сжимается целиком. Это середина между «каждый файл отдельно» (быстрая ленивая загрузка, хуже
сжатие) и «всё одним куском» (лучше сжатие примерно на 10-20%, но при старте распаковывается всё).

- Модули, которые грузятся вместе (по графу импортов), кладутся в один блок до ~16 КБ исходного текста.
- Крупный модуль (больше порога) идёт отдельным блоком.
- Ресурсы, уже сжатые (`.cimg` с RLE, `.dfpwm`), идут методом 0.
- Порог и группировка выбираются по замерам шага 0 и записываются сюда.

Методы (как в 03-file-formats.md): 0 без сжатия, 1 быстрый (`lzfast`), 2 сильный (`deflate`). Для кода по умолчанию метод выбирается
по замеру: если `deflate` распаковывается в CC достаточно быстро, везде 2.

## Ленивая загрузка

- При монтировании читаются только заголовок, манифест и таблицы.
- Модуль запрашивается загрузчиком: распаковывается его блок, все файлы блока кладутся в кэш памяти (слабая таблица с ограничением
  по объёму), загружается Lua.
- Кэш общий для системы, освобождается при нехватке памяти.

## Код внутри

- Только готовый Lua: выпускная сборка Cubic (минифицированная) или Lua автора как есть (по желанию минифицированный нашим минификатором).
- `.cub` в пакет не кладутся никогда. Исходники для отладки живут у автора и в Cobble.
- **Карты строк**: для минифицированного кода таблица «строка Lua -> файл и строка исходника». Обработчик ошибок (crash, crashbox)
  переводит место ошибки по карте. Карту можно не включать (флаг), тогда ошибки показывают место в Lua.

## Хранение на компьютере

Три способа, выбираются при установке системы и потом для каждого пакета в «Настройки → Хранилище»:

| Способ | Как лежит | Когда |
|---|---|---|
| сжато | `.cpk` как есть, CFS монтирует его папкой только для чтения | мало места (1 МБ) |
| распаковано | файлы пакета лежат обычными файлами | много места, быстрее старт |
| авто (по умолчанию) | часто используемые пакеты распакованы, остальные сжаты, пока хватает места | всегда разумно |

Ядро и загрузчик (`cubeos.boot`, `cubeos.kernel`, рантайм Cubic, распаковщик) всегда распакованы: система должна стартовать без
распаковщика, а при порче архива загрузиться в режим восстановления.

## Запуск `.cpk` без установки

Как в 03-file-formats.md: двойной клик монтирует архив во временную папку и запускает `entry`. На этом же построен `stew try`.

## Что проверить на шаге 0

- Реальный минимальный размер файла в CC:Tweaked и CraftOS-PC.
- Размер всего `lib` в трёх вариантах (по файлу, блоками, целиком) после выпускной сборки (`tools/dist_measure.lua` уже даёт часть).
- Время распаковки `deflate` и `lzfast` на 100 КБ кода в CraftOS-PC, не превышает ли сторожевой таймер «too long without yielding»
  (распаковщик должен уступать управление).
- Сколько памяти занимает кэш модулей при запущенном рабочем столе.
