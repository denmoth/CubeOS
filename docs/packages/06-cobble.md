# Каталог Cobble

Официальный каталог пакетов CubeOS. Отдельный репозиторий на GitHub (рабочее имя `cobble`, владелец решит аккаунт). Бесплатно,
HTTPS, CC скачивает с GitHub без настроек. В `sources.json5` по умолчанию первым: `{ name: "cobble", kind: "cobble", trust: "official" }`.

## Раскладка репозитория

```
index.json5                 общий каталог: все пакеты, версии, адреса .cpk, хэши, размеры, разрешения (генерирует CI, руками не правят)
packages/<id>/
  recipe.json5              откуда собирать: репозиторий автора и коммит/тег, или папка src/ здесь же; владелец пакета (GitHub логин)
  src/                      исходники, если автор публикует прямо в Cobble (так работает публикация из игры)
  icon.cimg, screenshot.cimg  для магазина (необязательно)
owners.json5                кто владеет каким id (для автоматического принятия обновлений)
.github/workflows/build.yml сборка и проверка
tools/                      сборщик (stew pack в CraftOS-PC headless), генератор индекса
```

Готовые `.cpk` лежат в **GitHub Releases** (тег `<id>-<version>`), не в git: репозиторий не раздувается.
Системные пакеты (`cubeos.*`) собираются из этого репозитория CubeOS по тегу версии системы тем же инструментом
(`tools/build_packages.lua`).

## Сборка в Actions

На каждый PR:
1. Собрать `.cpk` из исходника (никто не подсовывает готовый архив).
2. Проверить: манифест, имя не занято чужим, `cubeos.*` только от владельцев проекта, размер не больше лимита (предложение: 256 КБ на
   пакет, крупнее по согласованию), Lua загружается, зависимости есть в каталоге, нет обращений к запрещённым API без разрешения.
3. Оставить в PR комментарий: размер, разрешения, разница с прошлой версией (новые разрешения выделены).

После слияния: выложить `.cpk` в Releases, пересобрать `index.json5`.

**Принятие:**
- новый пакет: проверяет человек (владелец проекта);
- обновление своего пакета (логин автора есть в `owners.json5`) без новых разрешений: принимается автоматически, если проверки
  прошли;
- обновление с новыми разрешениями: проверяет человек.

## Публикация прямо из игры

Токен GitHub в игру не попадает. Посредник это маленький Cloudflare Worker (бесплатный тариф), рабочее имя `cobble-gate`.

**Вход (один раз на компьютер):**
1. `stew login` → Worker запускает вход GitHub через device flow и возвращает короткий код.
2. Игрок открывает на телефоне или ПК `github.com/login/device` и вводит код.
3. Worker хранит токен GitHub у себя, а компьютеру выдаёт свой ключ публикации (`cobble key`). Ключ лежит в защищённом
   хранилище CubeOS (docs/14-data-protection.md), его можно отозвать (`stew logout`, или на сайте Worker).

**Публикация:**
1. `stew publish <папка>`: локально `stew pack --check` (те же проверки, что в CI), показ манифеста, размера, разрешений.
2. Отправка исходников (не `.cpk`) одним архивом `.cbx` в Worker с ключом.
3. Worker создаёт ветку и PR в Cobble от имени пользователя (`packages/<id>/src/`), возвращает адрес PR.
4. `stew publish --status`: состояние проверки и принятия. После слияния пакет появляется в каталоге у всех.

Ограничения Worker: размер загрузки (как лимит пакета), частота (несколько публикаций в час на ключ), только папка своего пакета.

## Что решить владельцу позже

- Аккаунт или организация GitHub для `cobble` и Worker.
- Лимит размера пакета.
- Нужны ли оценки и отзывы (не в первой версии).
