# Работа с Git

## Ветки

- `main`: стабильная ветка. Прямые коммиты не делаем (кроме самого первого).
- `feat/<тема>`: новая функциональность.
- `fix/<тема>`: исправления.
- `docs/<тема>`: документация.
- `refactor/<тема>`, `chore/<тема>`: остальное.
- `release/<x.y>`: подготовка выпуска (при необходимости).

Ветка создаётся от `main`, в `main` возвращается через слияние (желательно PR/merge-request, даже в одиночной работе: так история ясна).

## Коммиты

Стиль: **Conventional Commits** (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`).

Пример: `feat(vfs): add symlink resolution`.

## Версии и теги

- SemVer: `v0.1.0-alpha`, `v0.1.0`, `v1.0.0-rc.1`.
- Тег ставится на `main` при выпуске.
- Список изменений в `CHANGELOG.md` (создаётся при первом выпуске).

## Что в репозитории

- Исходники ОС, компилятор, документация, тесты.
- Не храним: сборки (`build/`, `dist/`), временные файлы.
- Концы строк LF (см. `.gitattributes`).
