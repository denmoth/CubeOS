# Ядро CubeOS

Код: `lib/kernel/` (`init.cub` ядро, `sys.cub` вызовы для программ, `cc.cub` источник событий CC). Тесты `tests/cases/lib_kernel*.cub`, демонстрация в игре `game/kernel_demo.lua`. Решения D139–D148 в [08-decisions-log.md](../08-decisions-log.md).

## Что делает ядро простыми словами

В CC компьютер запускает одну программу за раз; если она долго не отдаёт управление (около 7 секунд), CC убивает её. Ядро позволяет нескольким программам работать «одновременно» (по очереди, маленькими порциями), следит, чтобы никто не завис, раздаёт события (клавиши, мышь, сеть, диски) и связывает программы между собой.

## Устройство

- **Процесс** это сопрограмма Lua. Есть номер (pid), имя, пользователь (субъект CFS), вид файловой системы (`cfs.view`), родитель и дети, очередь событий и почта.
- **Планировщик** кооперативный по кругу. Программа уступает управление при системных вызовах (`sleep`, `wait_event`, `receive`, `wait`) и автоматически: код на Cubic, скомпилированный с `--yield` (`opts.yield`), каждые 256 итераций цикла вызывает `rt.tick()`, а тот, если квант (по умолчанию 50 мс) вышел, уступает ядру. Программа, которая вообще не вызывает ядро, всё равно вытесняется.
- **События.** Ввод (клавиши, символы, вставка, мышь) идёт только активной программе (фокусу) и копится в её очереди, если она занята; остальные события (rednet, диски, периферия, таймеры CC) получают программы, которые ждут их в этот момент. Очередь ограничена (256).
- **Фокус** принадлежит программе с интерфейсом (`ui`); новая такая программа берёт его себе, `focus_next()` переключает, при завершении фокус переходит дальше.
- **Паузы** (`sleep`, таймауты `wait_event` и `receive`) считает само ядро по часам (`opts.clock`), в настоящем CC один таймер CC на ближайшее время.
- **Сообщения.** `send(pid, msg)` кладёт в почту получателя, `receive(timeout)` достаёт. Службы: `register(name)` и `lookup(name)`.
- **Завершение.** `exit`, возврат из функции (код выхода), сбой (исключение, причина сохраняется). Дети умирают с родителем, кроме `detached`. Освобождаются блокировки CFS и имена служб. Сведения о завершённых процессах хранятся (последние 64), `wait(pid)` отдаёт код и ошибку.
- **kill.** `term`: событие `terminate`, затем после паузы (`grace_ms`, 3 с) принудительно; `kill`: сразу. Убивать чужие процессы может администратор, система или владелец.
- **Права.** Запуск процесса от имени другого пользователя только у `system`. Лимит процессов (по умолчанию 64).

## «Не отвечает»

- Программа считается зависшей, когда событие в её очереди ждёт дольше `hung_ms` (по умолчанию 5 секунд), а она его не берёт. Ядро один раз вызывает `on_hung(proc)`; оболочка показывает вопрос.
- Ответ: `answer_hung(pid, "wait")` (ждать, таймер заново), `"snooze"` (не спрашивать `snooze_ms`, по умолчанию 5 минут, настраивается), `"kill"` (закрыть).
- **Лаг сервера не вина программы.** Если между тиками ядра прошло больше `lag_ms` (2 с), ядро решает, что подвис сервер, сдвигает отметки времени событий и не обвиняет программы в течение `hung_ms`.
- Программа, которая вообще не отдаёт управление (код без `--yield`), попадает под предел CC («Too long without yielding»): в Cobalt эта ошибка перехватывается, процесс завершается как сбой, ядро и остальные программы продолжают работать.

## Вызовы для программ (`sys`)

| Вызов | Действие |
|---|---|
| `yield()`, `sleep(сек)` | уступить, пауза |
| `wait_event(фильтр, таймаут)` | ждать событие; возвращает имя и аргументы |
| `spawn(fn, args, opts)`, `wait(pid)`, `exit(код)`, `kill(pid, mode)` | процессы |
| `send(pid, msg)`, `receive(таймаут)` | сообщения |
| `register(name)`, `lookup(name)` | службы |
| `getpid()`, `info()`, `ps()`, `now()` | сведения |
| `set_focus(pid)`, `focus()` | фокус |
| `view()`, `out(text)` | вид файловой системы, стандартный вывод |

Программа на Cubic из исходника: `kernel:spawn_source(src, name, args, opts)`; в ней доступны `sys` и `args`.

## Использование

```cubic
import kernel
import kernel.cc as cckernel

k = kernel.new({pull: cckernel.pull, rt: cubic.rt, cubic: cubic, fsys: fsys})
pid = k:spawn_source("sys.out('hello')", "hello", [], {ui: true})
k:run()
```

Для тестов вместо `run()`: `k:run_ready()`, `k:feed(событие...)`, `k:tick()` и свои часы (`opts.clock`).

## Ограничения

- Вытеснение работает только в коде, скомпилированном с `yield`. Плотный цикл на чистом Lua без вызовов ядра не вытесняется (его остановит предел CC).
- Нет приоритетов, нет настоящей изоляции памяти (всё в одной виртуальной машине Lua, песочница это отдельная задача, см. [12-permissions-capabilities.md](../12-permissions-capabilities.md)).
- Стандартный ввод и вывод пока простые (`sys.out`); терминал и конвейеры придут вместе с текстовой оболочкой.
