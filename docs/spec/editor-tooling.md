# Данные для редакторов

Компилятор уже разбирает код, знает типы и заголовки. Чтобы авторам редакторов не писать свой разборщик, всё это отдаётся наружу модулем `cubic.tooling` (файл `src/cubic/tooling.lua`) и командами `cubic` с выводом JSON. Плагин для конкретного редактора остаётся тонкой обёрткой.

Строки и столбцы считаются с единицы. Столбец это номер байта в строке (для UTF-8 это байты, не символы). Пустой список в JSON приходит как `[]`, пустая таблица тоже.

## Что отдаётся

| Функция | Команда | Назначение |
|---|---|---|
| `language()` | `cubic language` | словарь языка: ключевые слова по группам, константы, встроенные имена, глобалы CC, операторы, сниппеты, правила отступов |
| `textmate()` | `cubic grammar` | готовая грамматика TextMate (`source.cubic`) для VS Code, Sublime, GitHub; строится из словаря, поэтому не расходится с языком |
| `highlight(src)` | `cubic tokens файл` | токены для подсветки |
| `symbols(src)` | `cubic symbols файл` | структура файла: функции, методы, классы, поля, импорты, переменные |
| `diagnostics(src, file, opts)` | `cubic diagnostics файл` | ошибки и предупреждения с координатами |
| `complete(src, line, col, opts)` | `cubic complete файл --line=N --col=M` | подсказки на Tab |
| `signature(src, line, col, opts)` | `cubic signature файл --line=N --col=M` | параметры вызова под курсором |
| `hover(src, line, col, opts)` | `cubic hover файл --line=N --col=M` | тип и описание имени под курсором |

Команды читают `cubic.json5` проекта, так что подсказки учитывают `mods`, `headers` и `libs`, как и сама компиляция.

## Подсветка

Разбор терпит ошибки: недописанная строка, лишний символ или незакрытая скобка не ломают подсветку остального файла (в отличие от компиляции). Комментарии входят в результат. Многострочные строки приходят по одному токену на строку.

Токен: `{kind, line, col, len, text}` и необязательные поля `decl` (это объявление), `group` (для ключевых слов: `control`, `declaration`, `operator`), `mod` (`constant`), `call`, `open` (строка не закрыта), `interp` (скобка интерполяции f-строки).

Виды (`kind`): `keyword`, `constant`, `string`, `escape`, `number`, `comment`, `directive` (`#!strict`), `operator`, `punct`, `variable`, `parameter`, `function`, `method`, `class`, `property`, `decorator`, `namespace`, `type`, `builtin`, `api` (глобалы CC), `self`, `luacode`, `error`.

Смысл имён определяется по соседним токенам: имя после `def` это функция, после `.` свойство или метод, перед `(` вызов, в `import` часть пути модуля, после `:` в параметрах тип. Внутри `{}` f-строки код подсвечивается как обычный, формат (`:>5`) как строка.

Блоки `lua:` приходят токенами `luacode` построчно, а отдельным списком `embedded` с диапазонами строк: редактор может включить подсветку Lua внутри них.

## Символы

Элемент: `{name, kind, line, col, len, end_line, detail, doc, exported, container, params, returns, ...}`.
Виды: `function`, `method`, `class`, `field` (из `self.x = ...` в методах), `variable`, `constant`, `import`. `detail` это готовая сигнатура (`add(a: num, b: num = 1) -> num`), `doc` это комментарии `#` сразу над определением. Работает по токенам, поэтому доступно и когда в файле есть ошибки.

## Диагностика

`{severity = "error" | "warning", line, col, end_col, message}`. Синтаксическая ошибка одна (разбор останавливается на первой). Ошибки типов возвращаются все сразу, предупреждения компилятора тоже (скрытые встроенные имена, затёртые функции).

## Автодополнение

`complete` возвращает `{context, prefix, replace = {line, col, end_col}, items}`.

`context`:
- `member`: после `.`, `?.` или `:`. Члены определяются по типу выражения слева, то есть по настоящему выводу типов checker: поля и методы классов, пространства имён CC (`term.`), методы строк, поля записей, экспорты модулей, импортированных через `import`;
- `name`: имена, видимые в этой точке (локальные, затем глобальные из заголовков: CC, моды, проект), встроенные, ключевые слова и сниппеты;
- `import`: имена модулей из корней загрузчика (`opts.loader`), либо список `opts.modules`;
- `import_names`: после `from модуль import`, экспорты этого модуля;
- `string`, `lua`: внутри строки, комментария и блока `lua:` подсказок нет.

Элемент: `{label, kind, detail, snippet?, doc?, sort}`. `snippet` это текст со вставками `${1:имя}` (формат VS Code) для функций (по обязательным параметрам) и для шаблонов `def`, `class`, `for`, `forr`, `try` и других. `sort` задаёт порядок: локальные, затем глобальные, встроенные, ключевые слова. Список уже отфильтрован по набранному началу слова.

Как это работает: файл обрезается на строке курсора, вместо неё подставляется служебный вызов `__cubic_probe(выражение)`, и checker в режиме strict сообщает тип выражения и видимые имена. Поэтому подсказки работают и в файле без `#!strict`, и пока остальной код ниже ещё не написан. Если код выше курсора синтаксически сломан, остаются подсказки из символов файла и заголовков.

## Подсказка параметров

`signature` вернёт `{signatures = {{label, params = {{name, type, optional}}}}, active}`; `active` номер аргумента под курсором. Для `obj:method(` первый параметр (`self`) не показывается.

## Наведение

`hover` вернёт `{text, type, signature?, doc?, range}`: тип выражения под курсором (с учётом сужения `T?`), для своих функций и классов ещё сигнатуру и комментарий над определением.

## Ограничения

- Одна ошибка синтаксиса за раз: разбор не восстанавливается после неё.
- Столбцы в байтах: клиентам, считающим в символах UTF-16, нужно пересчитать.
- Подсказки и hover видят только то, что известно checker'у: код в `lua:` и значения `any` остаются без членов.
- Пока нет долгоживущего сервера (LSP): каждая команда запускается отдельно. Обёртка LSP на Node поверх этих команд возможна, ядро для неё готово.
