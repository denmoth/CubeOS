# Инструментарий: компилятор и сборка

## Компилятор Cubic

Этапы:
1. Лексер с токенами `INDENT/DEDENT`.
2. Парсер строит AST.
3. Проверка типов (в `strict` участках).
4. Генератор пишет Lua.

Компилятор написан на Lua. Работает на ПК (для разработки) и на самом компьютере CC. Результат кешируется, пересборка при изменении исходника.

## Реализация 0.3.0

Код в `src/cubic`: `lexer.lua`, `parser.lua`, `checker.lua` (типы), `codegen.lua`, `rt.lua` (рантайм), `builtins.lua`, `headers/*.cuh`, `init.lua` (загрузчик). Компилятор работает на Lua 5.1/5.2 без внешних зависимостей, поэтому запускается и в CraftOS-PC, и в игре.

Консоль (на ПК через CraftOS-PC): `tools/cubic.sh compile|check|run файл.cub [вывод.lua] [--minify] [--keep-comments] [--map] [--strict]`.
Тесты: `tools/test.sh [фильтр]`, наборы в `tests/cases` (`.cub` + `.out`, `.err`, `.rterr`, `.exports`, `.opts`, `.luahas`, `.luahasnot`). Каждый обычный тест прогоняется ещё раз с `--minify`.

## Cubic 1.0 (2026-10-18)

Главное: размер и скорость готового кода, удобство письма. Совместимость с 0.3 не держалась (альфа), `lib` переведён автоматически.

- **Сборки.** По умолчанию (разработка, тесты, загрузка `.cub` на компьютере) код проверочный: `len()` словаря даёт понятную ошибку
  «use count(d)». Выпуск (`opts.release`, пакеты для установки) пишет голый `#`. Установленная система получает готовый
  минифицированный Lua, компилятор ставится отдельным необязательным пакетом.
- **Строки совпадают.** Без минификации строка N сгенерированного Lua это строка N исходника `.cub` (код одной строки пишется в одну
  строку Lua, пропуски пустые): ошибка в любой момент работы показывает настоящую строку без карт. Имя куска короткое
  (`apps/notes/editor.cub`), а не обрезанный Lua путь вроде `editor.c`. Минифицированный код идёт с картой строк.
- **Меньше рантайма в горячем коде:** `len(x)` это `#x`; `for x in список` числовой цикл (втрое быстрее итератора-замыкания);
  `a ?? 5` (простое имя или поле слева, значение справа) без вызова функции; подпись функции для именованных аргументов
  (`__rt.sig`, слабая таблица на каждое создание функции, в 7 раз медленнее простой функции) только экспортам, конструкторам и
  модулям, где такие вызовы есть; короткие ссылки `__floor`, `__type` и т. п. только если код ими пользуется.
- **Области как в Python** и `outer x` (см. grammar.md). Переход: `tools/migrate_scope.py` (вставляет `outer`, где старый код
  менял внешнюю переменную и читал её до присваивания), отчёт `tools/scope_report.lua` (где присваивание стало своей переменной).
- **Свободные имена:** `copy`, `len`, `str`, `num`, `load`, `next` и т. п. можно брать для своих переменных.
- Замеры на всём `lib` (189 файлов, `tools/dist_measure.lua`): исходник 2,08 МБ; готовый минифицированный Lua был 1,58 МБ, стал 1,50 МБ;
  одним сжатым архивом около 450 КБ (вместе с assets и sys около 570 КБ: система целиком помещается на компьютер в 1 МБ).
  Скорость (CraftOS-PC): перебор списка 0,14 -> 0,05 с на 3 млн элементов, `??` в 1,5 раза быстрее, создание функций в 7 раз.

## Флаги

| Флаг | Действие |
|---|---|
| (по умолчанию) | Комментарии вырезаются |
| `--keep-comments` | Комментарии сохраняются |
| `--minify` | Переименование локальных, удаление пробелов, максимальное сжатие |
| `--map` | Файл карты (сопоставление строк) |

Минификатор **не трогает**:
- поля таблиц (`obj.name`);
- глобальные имена;
- идентификаторы внутри `lua:` вставок.

После `--minify` номера строк в ошибках не совпадают с исходником, поэтому нужна `.map` рядом.

Цель минификации: размер (лимит диска CC), не защита кода.

## Для редакторов

Подсветка, символы, диагностика, автодополнение, подсказка параметров и наведение доступны модулем `cubic.tooling` и командами `cubic tokens|symbols|diagnostics|complete|signature|hover|language|grammar` (JSON). Подробности: [editor-tooling.md](editor-tooling.md).

## Пометка в скомпилированных файлах

Первая строка результата: `-- Generated by Cubic 0.3.0 from app.cub (size=1234 adler32=XXXXXXXX). Do not edit.` По ней видно, что файл сгенерирован, и ОС может проверить, что он соответствует исходнику (`parse_banner`, `is_up_to_date`), не перекомпилируя. Отключается `opts.banner = false`.

## Проект: cubic.json5

Поля: `mods` (заголовки аддонов), `headers` (свои `.cuh`), `strict`, `minify`, `libs` (дополнительные каталоги модулей), `cache` (каталог кэша заголовков). Файл ищется вверх от исходника.

## Источники ошибок

- Генератор сохраняет соответствие строк (кроме `--minify`), чтобы ошибки указывали на `.cub`.
- Трассировка исключений показывает исходный файл и строку.

## Сборка пакетов

- `cubic build <папка>` собирает `.cpk`.
- `stp build` собирает установщик (см. [../03-file-formats.md](../03-file-formats.md)).
- Файлы читаются и пишутся в бинарном режиме.

## Заголовки

Файлы `.cuh` (типы внешних API) читаются проверкой типов в `strict` участках.

## Инструменты (планы)

- REPL.
- Форматтер.
- Расширение для VS Code: подсветка, автодополнение.
- Тест-фреймворк.
- Генератор описаний типов для CC API из документации.

## Автоматические yield

Опция компилятора: в циклах без обращения к событиям вставлять проверку времени и `yield`, чтобы избежать ошибки `too long without yielding`. Накладные расходы нужно измерить **(проверить)**.
