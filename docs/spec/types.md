# Типы, strict и заголовки .cuh

Статус: **реализовано** в `src/cubic/checker.lua` (компилятор 0.3.0).

## Принцип

Типы проверяются только при компиляции и на скорость не влияют. Код без аннотаций работает как раньше. Режим включается построчно:

```
#!strict      # с этой строки код проверяется строго
...
#!loose       # с этой строки не проверяется
```

Или блоком (удобно для кусочка внутри файла):

```
strict:
    total: num = 0

loose:
    q = something_untyped
```

`--strict` в консольной утилите включает проверку для всего файла. Значения, пришедшие из нестрогого участка, имеют тип `any` (ошибок не вызывают). Ошибки собираются и выводятся списком (до 20).

## Типы

| Запись | Смысл |
|---|---|
| `num`, `str`, `bool`, `nil` | примитивы (один числовой тип) |
| `any` | любое значение, проверка отключена |
| `list[T]` | список |
| `dict[K, V]` | словарь |
| `{x: num, y: num}` | запись (известные поля); литерал `{x: 1, y: 2}` сам получает такой тип |
| `T?` | `T` или `nil` (то же, что `T \| nil`) |
| `A \| B` | один из типов |
| `fn(num, str) -> bool` | функция (имена параметров необязательны: `fn(x: num) -> num`) |
| `Point` | экземпляр класса |
| `Error` | встроенный класс ошибок (поле `message: str`) |

Псевдонимы: `type Pair = {a: num, b: num}`.

## Что проверяется

- Присваивание и инициализация: `x: num = "a"` ошибка. Переменная без аннотации получает тип первого значения (`nil` и пустые литералы дают `any`).
- Вызовы: число аргументов, типы, пропущенные обязательные параметры, именованные аргументы (`no parameter named`), конструкторы классов.
- `return` против объявленного `-> T`.
- Операторы: арифметика только для `num`, `..` для `str` и `num`, сравнения `<` для одинаковых типов.
- Доступ: поля записей и классов (`no member`), индексация, срезы, `:` методы (в том числе методы строк).
- **Значение с `nil`:** `s: str?` нельзя использовать без проверки (`may be nil`).
- **Сужение:** после `if x != nil`, `if x == nil: return`, `if x:`, `if type(x) == "number"`, `isinstance(x, C)` тип сужается. Сужение сбрасывается присваиванием.
- Неизвестное имя в strict участке: ошибка (`unknown name`), список глобалов задают заголовки.
- Классы: поля берутся из объявлений `x: num` в теле класса и из присваиваний `self.x = ...` в методах (тип выводится по литералу или по аннотации параметра). Наследование проверяется (`a: Animal = dog`).

Типы функций без аннотации возвращаемого значения считаются `any`: пишите `-> T`, чтобы вызывающий код проверялся точнее.

## Заголовки .cuh

Описывают типы внешнего API (то, что нельзя вывести из кода). Синтаксис похож на сам Cubic, но без тел функций:

```
# comments
def print(*args: any)
def tonumber(v: any, base: num?) -> num?

class FileHandle:
    readAll: fn() -> str?
    close: fn()

open namespace fs:                 # open: неизвестные члены разрешены (тип any)
    def exists(path: str) -> bool
    def open(path: str, mode: str) -> FileHandle?
    pi: num                        # значение
```

- Функции с несколькими возвращаемыми значениями описываются как `-> any`.
- `*rest: T` в параметрах это переменное число аргументов.
- Встроенные заголовки лежат в `src/cubic/headers`: `lua.cuh` (стандартная библиотека Lua и расширения CC для `os`) и `cc.cuh` (`term`, `fs`, `peripheral`, `rednet`, `redstone`, `colors`, `textutils`, `shell`, `http`, `turtle` и другие). Покрытие частичное: недостающее добавляется в файлы или подключается через `opts.headers` (пользовательские `.cuh` для аддонов).

## Ограничения

- Нет обобщённых (generic) пользовательских типов и перегрузок.
- Вывода типа возвращаемого значения нет.
- Сужение работает для простых имён, не для полей (`self.x`).
- Список типов CC API неполный; поддержку аддонов (Advanced Peripherals и др.) нужно описывать отдельными `.cuh`.
