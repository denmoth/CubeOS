# Загрузка, вход и сессии

Код: `lib/boot/` (`init.cub` загрузка, `state.cub` журнал загрузок, `auth.cub` пользователи и пароли, `session.cub` сессии, `services.cub` службы, `greeter.cub` и `console.cub` текстовый вход). Тесты `tests/cases/lib_boot*.cub`, демонстрация в игре `game/boot_demo.lua`. Решения D151–D160 в [08-decisions-log.md](../08-decisions-log.md).

## Этап 1: `startup`, `stage1.lua`, `rescue.lua`, `runtime.lua`

Код: каталог `sys/` репозитория (ставится в `/startup.lua` и `/cubeos/sys/boot/`). Тест `tests/unit/stage1.lua` (подставные `os`, `fs`, `term`). Решения D204, D207, D208, D210.

```
/startup.lua                    находит и запускает этап 1; нет или упал: rescue.lua; нет и его: CraftOS (системы нет) или запертость (если есть users.conf)
  └─ /cubeos/sys/boot/stage1.lua   окно клавиши, меню, выбор загрузчика, при сбое восстановление
       ├─ загрузчик (de.conf: boot, по умолчанию /cubeos/sys/boot/stage2.lua) = stage2, получает ctx
       └─ rescue.lua              восстановление с паролем администратора
            └─ runtime.lua        откуда брать код системы; проверка пароля (boot.recovery_login)
```

- **`startup.lua`** подменяет `os.pullEvent` на `os.pullEventRaw` (Ctrl+T не прерывает загрузку и восстановление) и возвращает результат: `"craftos"` (вернуться в оболочку CraftOS), `"reboot"`, иначе выключение. Это несколько строк, а не одна: одна строка не может вернуть `os.pullEvent` и разобрать результат.
- **`stage1.lua`**: чистый Lua без библиотек. Читает плоские ключи из `boot.conf` и `de.conf` (JSON5 со строками, числами, `true/false`, комментариями `//`). Около `key_window_ms` (1000) слушает клавишу меню (`menu_key`, по умолчанию `delete`, D218: F2 в Minecraft делает скриншот) и Ctrl; на последней строке экрана серая подсказка. Ctrl: сразу восстановление. Delete: меню (Up/Down/Enter, пункты CubeOS, CubeOS (terminal) (полноэкранный терминал вместо рабочего стола CDE на эту загрузку), CubeOS (safe mode), CubeOS (input log) (журнал ввода на эту загрузку, D220), Recovery, CraftOS; таймаут `menu_timeout` секунд выбирает первый пункт, любая клавиша его отменяет). Пункт CraftOS идёт через `rescue.lua` с `gate: true` (пароль администратора), при отказе возврат в меню.
- **Ключи `boot.conf` этапа 1:** `menu` (`"key"` по умолчанию: клавиша меню открывает меню; `"always"`: меню каждый раз; `"off"`: клавиша игнорируется, Ctrl остаётся), `menu_key`, `key_window_ms`, `menu_timeout`, `source` (для `runtime.lua`, каталог репозитория, по умолчанию `/repo`). **`de.conf`:** `boot` путь к загрузчику DE.
- **Дискеты (`sys/boot/diskboot.lua`, D224).** Загрузка с дискет самого ROM (`shell.allow_disk_startup`) подменяет `/startup.lua` и обходит пароль, поэтому `stage1` выключает её при каждой загрузке (`rom_disk_startup: true` в `boot.conf` оставляет как есть) и пишет об этом в `boot.log`. Своя загрузка: `disk_boot` `"off"` (по умолчанию), `"trusted"` (только доверенные), `"password"` (доверенные сразу, остальные после пароля администратора), `"all"` (любая дискета с `startup.lua` или `startup`). Доверенные: `/cubeos/sys/cfg/trusted_disks.conf`, строки `<номер дискеты> <sha256 файла startup> [метка]`; изменённый `startup` уже не доверенный. В безопасном режиме дискеты не запускаются. Дискету запускает `startup.lua` (`shell.run`), после неё остаётся CraftOS.
- **Предупреждение (D225).** Пункт CraftOS и загрузка с недоверенной дискеты сначала показывают предупреждение (CubeOS не защищает компьютер в CraftOS, совет выключить компьютер после работы) и спрашивают `y`, потом пароль администратора.
- **Загрузчик** вызывается как `loadfile(path)(ctx)`; `ctx = {caps: {pixel, color}, mode: "safe"|nil (выбор в меню), menu: bool, boot_dir, conf_path}`. Возврат: `nil` (питание уже выключено), `"reboot"`, `"craftos"` либо `"recovery", причина` (этап 1 откроет восстановление). Исключение в загрузчике тоже ведёт в восстановление с текстом ошибки. Загрузчик не должен пользоваться `sleep`/`os.pullEvent`, только `pullEventRaw` (иначе Ctrl+T бросит «Terminated»; это тоже попадёт в восстановление, но лучше не провоцировать).
- **`rescue.lua`**: аргументы `reason`, `gate`. Если нет `users.conf`, открыто. Иначе пароль проверяет `runtime.lua` (`recovery_login`: три попытки); нет runtime или проверка упала: **заперто** (перезагрузка через 3 с). После пароля меню: оболочка CraftOS, перезагрузка, выключение; при `gate` сразу `"craftos"`. Если `rescue.lua` отсутствует, а `users.conf` есть, этап 1 тоже запирает (нажатие клавиши перезагружает); без `users.conf` отдаёт CraftOS, чтобы систему можно было установить.
- **`runtime.lua`** это единственное место, знающее, откуда берётся код системы. Сейчас разработческий: исходники репозитория (`source`), компиляция Cubic на лету. В установленной системе (шаг 9, D187) заменяется вариантом с готовым Lua; интерфейс тот же: `import(имя)`, `recovery_login(console, {root})`.
- Меню этапа 1 рисуется текстом; пиксельное меню возможно позже силами DE (`ctx.caps.pixel`).

## Этап 2: загрузчик `stage2.lua` и экран загрузки

Код: `sys/boot/stage2.lua`, `lib/boot/splash.cub`, `rt.plan/preload` в `runtime.lua`. Тесты `tests/unit/stage2.lua` (вся цепочка на настоящих runtime, CFS, ядре и входе), `tests/cases/lib_boot_splash.cub`, `lib_boot_console.cub`. Снимки экрана: `tools/boot_shots.sh` (`build/ui_boot_*.png`). В игру цепочку ставит `game/install_dev.lua` (`remove` убирает).

1. Чистит экран (до экрана загрузки только чёрный, никакого текста) и подгружает минимум (`version`, `json5`, `boot.splash`), открывает **экран загрузки**. Веса этапов полосы берутся из замера прошлой загрузки (`/cubeos/var/boot.timing`), поэтому полоса идёт ровно по времени; `boot.conf: stage_weights` важнее замера.
2. Подгружает модули по этапам с весами (`libs`, `fs`, `kernel`, `setup`, `services`, `login`; вес по умолчанию 0.30/0.10/0.25/0.05/0.25/0.05, переопределяется `stage_weights` в `boot.conf`). `rt.preload` строит порядок по строкам `import` (зависимости раньше зависимых) и после каждого модуля отдаёт управление CC: так не бывает «Too long without yielding».
3. Строит CFS (`host` на корень данных, `tmp` в памяти, права по умолчанию, каталоги `/cubeos/...`), вызывает `boot.new({mode, on_ready, ...})` и `start()`. Режим `recovery`: возврат `"recovery", причина` этапу 1.
4. Запускает ядро и процесс **`bootscreen`**: ведёт полосу по состоянию служб (`system.services:list()`), по `on_ready` (службы подняты, отметка загрузки снята) завершает экран (`splash:done(sys.sleep)`, `close`), пишет замер этапов в `/cubeos/var/boot.timing` (по нему подбираются `stage_weights`).
5. Любая ошибка этапа: экран ошибки с текстом и «нажмите клавишу», возврат `"recovery", текст`.

**Экран загрузки** (`boot.splash`, D245): `new({caps, term, assets, clock, title})` возвращает обёртку с методами `open`, `progress(доля, подпись)`, `message(текст)`, `tick()`, `done(pause)`, `error(текст)`, `close()`. Пиксельный вариант (CC: Graphics, по образцу сцены «Интро» из `examples/cgl_demo.cub`): тёмный фон с виньеткой и мерцающими звёздами, куб и надпись `CubeOS` с версией рисуются один раз номерами палитры (28 полос по ширине логотипа × 4 тона: три грани и надпись, номера 136..247; фон 100..123, звёзды 124..131, подписи 132..135). Каждый кадр меняет только цвета этих номеров: волна света идёт слева направо вместе с загрузкой (на фронте белый блик, за ним по логотипу бежит перелив), прогресс догоняет цель плавно и никогда не идёт назад. Подпись этапа обязательна: старая гаснет, новая проявляется; строка пояснения под ней. Финал (`done`) около секунды: волна до конца, вспышка (светлеет и фон), затухание в чёрный, поэтому переход ко входу без мигания. Ошибка: логотип краснеет, текст ошибки ниже. Текстовый вариант: логотип блоками телетекста (`lib/logo.cub`, общий с `fetch`) проявляется по столбцам (серый, белый фронт, свои цвета), полоса с половинками клеток (на чёрно-белом терминале `[###---]`). Обёртка `Guard` защищает загрузку: исключение в экране отключает его, у пиксельного перед этим пробуется текстовый. Контракт для DE: тот же набор методов, DE подменяет `boot.splash` (позже через `de.conf`).

**Ввод в процессах ядра.** `read` из CC внутри процесса ядра не работает (он ждёт события у CC, а не у планировщика), поэтому `TermConsole.bind(sys)` даёт консоль, читающую через `sys.wait_event` (символы, вставка, Backspace, Enter). `Boot` связывает консоль с процессом входа сам. `Boot` принимает `mode: "safe"` (выбор в меню) и `on_ready(system)`.

## Порядок загрузки

1. **Журнал загрузок.** `boot.state` помечает загрузку «начата» (`pending`). Файл `/cubeos/var/boot.state`.
2. **Режим.** По журналу выбирается обычная, безопасная или восстановление (ниже).
3. **Настройки** `/cubeos/sys/cfg/boot.conf` (JSON5): `autologin`, `lang`, `de`, `elevate_ms`, `rounds`, `title`.
4. **Пользователи** из `sys/cfg/users.conf`, пароли из `sys/sec/shadow.lock`, администраторы из `sys/sec/sudoers.lock`.
5. **Ядро** и менеджер сессий. В режиме восстановления ядро не запускается.
6. **Процесс `init`** (от имени `system`) запускает службы из `/cubeos/sys/services/*.conf` по зависимостям и ждёт готовности каждой.
7. **Процесс `login`** (с интерфейсом) ждёт завершения `init`, **снимает отметку «загрузка не закончена»**, показывает вход, после входа запускает оболочку сессии, ждёт её завершения и закрывает сессию; потом снова показывает вход.
8. Выключение или перезагрузка с экрана входа: сессии закрываются, службы останавливаются (просьба завершиться, через 3 с принудительно), загрузка помечается корректно завершённой, вызывается `power.shutdown` или `power.reboot`.

## Режимы

| Режим | Когда | Что происходит |
|---|---|---|
| обычный | прошлая загрузка дошла до входа | всё запускается |
| безопасный | одна подряд незавершённая загрузка | службы с `safe: false` не запускаются |
| восстановление | две подряд незавершённые загрузки или Ctrl при старте | ядро не стартует; стартовый файл проверяет пароль администратора (`boot.recovery_login`, три попытки; без учётных записей открыт) и открывает чистый CraftOS-шелл |

## Пользователи и пароли

- Запись пользователя: `name`, `display` (подпись, можно по-русски), `roles` (`user`, `guest`, ...), `groups`, `color`, `temp` (гость). Имя проверяется как имя в CFS (кириллица можно), без учёта регистра.
- Пароль: PBKDF2-HMAC-SHA256, запись `pbkdf2-sha256$раунды$соль$хэш` в `shadow.lock` (читает только система). Число раундов в `boot.conf` (`rounds`, по умолчанию 1000, около секунды в игре). Нет записи в shadow: пользователь без пароля.
- **PIN (D226):** `/cubeos/sys/sec/pins.lock` (имя -> {hash, fails}, только хэш), команда `pin set|remove`. Экран входа спрашивает PIN (`p` вместо PIN переходит к паролю); после 5 неверных PIN только пароль, верный пароль снимает блокировку. Пароль остаётся для `sudo`, восстановления и CraftOS. Способ входа в сессии: `login_method` `password|pin|remember|trusted`.
- **«Не спрашивать X минут» (D227):** поле учётной записи `remember_minutes` (команда `remember N|off`, нужен пароль), время последнего входа в `/cubeos/var/login.state`. **Автовход:** `boot.conf: autologin` (команда `sudo autologin ИМЯ|off`).
- **sudo (D231):** `SessionManager:elevate` (пароль) или `elevate_trusted` (вход был по паролю и `boot.conf: sudo_trust_login` не false); права 5 минут (`elevate_ms`). Терминал на время команды подменяет `fs` на вид с ролью admin. Системные настройки (`autologin`, `disk_boot`, `trusted_disks.conf`) пишет `SessionManager:account` системным `fsys`, только для команды, запущенной через `sudo`.
- Соль: из времени, счётчиков и `math.random` (в CC нет системного источника случайных чисел).
- После трёх неудач подряд вход замедляется: пауза 5 с, дальше вдвое, не больше минуты; во время паузы даже верный пароль отклоняется («locked»).
- Администраторы это список в `sudoers.lock`; обычный вход не даёт прав администратора.

## Сессии

Сессия это вход пользователя: субъект CFS, вид файловой системы с `$алиасами`, окружение и процессы.

- `open(имя, пароль)` проверяет пароль, создаёт профиль `/cubeos/users/<имя>/{home/{documents,pictures,videos,projects},apps,cache,cfg,data,desktop,trash}`, если его нет.
- **Гость** (`temp: true`) получает временный профиль `users/<имя>-<номер сессии>`, который удаляется при закрытии сессии.
- Несколько сессий одновременно, активна одна (`switch`). Закрытие сессии завершает её процессы.
- **Повышение прав** (`elevate`): пароль пользователя и членство в `sudoers.lock`; даёт роль `admin` на `elevate_ms` (по умолчанию 5 минут); процессы, запущенные после этого, получают права администратора. `drop_elevation` снимает досрочно. Диалог пароля показывает только ядро (оболочка вызывает `elevate`).
- Блокировка (`lock`/`unlock`): снимает повышение, запрещает запуск процессов, разблокировка по паролю.
- Процессы сессии запускаются с субъектом пользователя и его видом файловой системы (`sys.view()`).

## Службы

Манифест в `/cubeos/sys/services/<имя>.conf` (JSON5): `name`, `module` (модуль с `main(sys, args)`), `requires`, `after`, `restart` (`on-failure`, `always`, `never`), `max_restarts`, `restart_delay`, `ready` (`register` или `immediate`), `timeout`, `enabled`, `safe`.

- Порядок запуска по зависимостям; службы с нескольким одинаковым уровнем идут по имени; цикл и неизвестная зависимость попадают в журнал.
- Готовность: служба вызывает `sys.register(имя)`.
- Если нужная служба не запустилась, зависимая получает состояние `blocked`.
- Каждую службу ведёт надзиратель (процесс `svc-<имя>`): перезапуск по правилам, остановка при выключении.
- Состояния: `stopped`, `starting`, `running`, `failed`, `blocked`, `disabled`.

## Сессия с терминалом (`term.session`)

Оболочка сессии по умолчанию это терминал с оболочкой `cush`, работающий внутри процесса ядра (`stage2` передаёт `shell: (session) => term_session.program(session, {assets})`). Код `lib/term/session.cub`, тест `lib_term_session` (вход, команды, файлы в профиле, время и питание от служб, буфер обмена, Ctrl+T, выход).

- **fs поверх CFS.** Окружение совместимости получает `cfs.legacy_fs(sys.view())`: программы CraftOS работают с правами пользователя, симлинками и корзиной. Начальный каталог `$home` (`/cubeos/users/<профиль>/home`), приглашение `пользователь@метка-компьютера:~$`. Правила по умолчанию дают всем чтение `/rom` (программы и API CraftOS), чтение `/` и `/cubeos` (сами каталоги), `$user`-папку на запись; системные каталоги пользователю закрыты.
- **Ввод через ядро.** События идут через `sys.wait_event`; Ctrl+T приходит как `terminate` активной программе (оболочка прерывает команду, а не систему); выход из оболочки (`exit`) закрывает сессию и возвращает на экран входа. Если терминал упал, сессия сообщает «The terminal crashed: …», отчёт получает `crashd`.
- **Вызовы служб «через хозяина».** Программы и оболочка работают в сопрограмме `compat.proc`, а системные вызовы ядра можно делать только из процесса. Поэтому `timedatectl set-*` и `shutdown/reboot` кладут запрос в очередь хозяина и ждут событие `cubeos_reply`; цикл терминала выполняет запрос (`timed`, `powerd`) и отвечает. Время для `date` и `fetch` считается у себя по настройкам `timed`. Общий буфер обмена: текст, скопированный в терминале, уходит в службу `clipboard`, при старте терминал берёт оттуда текущий.
- **Настройки пользователя**: `$cfg/cush.conf` (JSON5): `aliases {имя: "команда"}`, `motd "строка после приветствия"`, `greeting false`; история `$cfg/cush_history`.
- Команды системы: `date`, `timedatectl`, `logs`, `shutdown` (`poweroff`), `reboot` (`restart`), `fetch`.

## Вход

Пока нет библиотеки интерфейса, вход текстовый (`TextGreeter` поверх `console`): список пользователей, ввод номера или имени, пароль звёздочками; при первой загрузке предлагается создать первого администратора. Тексты английские (D135). `console` это интерфейс (`write`, `write_line`, `clear`, `read_line(подсказка, скрыть)`) с реализациями `TermConsole` (настоящий терминал CC) и `ScriptedConsole` (тесты). Плиточный экран входа придёт с библиотекой интерфейса и займёт место `TextGreeter`.

## Использование

```cubic
b = boot.new({fsys: fsys, console: console, import: loader.import, shell: (session) => program,
              kernel: {pull: cckernel.pull, rt: cubic.rt, cubic: cubic}, power: {shutdown: ..., reboot: ...}})
system = b:start()
if system.mode == "recovery": ...         # проверить boot.recovery_login и открыть чистый CraftOS
else: system.kernel:run()
```

Эталон для настоящего CC: `game/boot_demo.lua` (папка данных `/cubeos-demo`, Ctrl при старте для восстановления).
