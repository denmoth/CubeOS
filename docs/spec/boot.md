# Загрузка, вход и сессии

Код: `lib/boot/` (`init.cub` загрузка, `state.cub` журнал загрузок, `auth.cub` пользователи и пароли, `session.cub` сессии, `services.cub` службы, `greeter.cub` и `console.cub` текстовый вход). Тесты `tests/cases/lib_boot*.cub`, демонстрация в игре `game/boot_demo.lua`. Решения D151–D160 в [08-decisions-log.md](../08-decisions-log.md).

## Этап 1: `startup`, `stage1.lua`, `rescue.lua`, `runtime.lua`

Код: каталог `sys/` репозитория (ставится в `/startup.lua` и `/cubeos/sys/boot/`). Тест `tests/unit/stage1.lua` (подставные `os`, `fs`, `term`). Решения D204, D207, D208, D210.

```
/startup.lua                    находит и запускает этап 1; нет или упал: rescue.lua; нет и его: CraftOS (системы нет) или запертость (если есть users.conf)
  └─ /cubeos/sys/boot/stage1.lua   окно клавиши, меню, выбор загрузчика, при сбое восстановление
       ├─ загрузчик (de.conf: boot, по умолчанию /cubeos/sys/boot/stage2.lua) = stage2, получает ctx
       └─ rescue.lua              восстановление с паролем администратора
            └─ runtime.lua        откуда брать код системы; проверка пароля (boot.recovery_login)
```

- **`startup.lua`** подменяет `os.pullEvent` на `os.pullEventRaw` (Ctrl+T не прерывает загрузку и восстановление) и возвращает результат: `"craftos"` (вернуться в оболочку CraftOS), `"reboot"`, иначе выключение. Это несколько строк, а не одна: одна строка не может вернуть `os.pullEvent` и разобрать результат.
- **`stage1.lua`**: чистый Lua без библиотек. Читает плоские ключи из `boot.conf` и `de.conf` (JSON5 со строками, числами, `true/false`, комментариями `//`). Около `key_window_ms` (1000) слушает клавишу меню (`menu_key`, по умолчанию `f2`) и Ctrl; на последней строке экрана серая подсказка. Ctrl: сразу восстановление. F2: меню (Up/Down/Enter, пункты CubeOS, CubeOS (safe mode), Recovery, CraftOS; таймаут `menu_timeout` секунд выбирает первый пункт, любая клавиша его отменяет). Пункт CraftOS идёт через `rescue.lua` с `gate: true` (пароль администратора), при отказе возврат в меню.
- **Ключи `boot.conf` этапа 1:** `menu` (`"key"` по умолчанию: F2 открывает меню; `"always"`: меню каждый раз; `"off"`: F2 игнорируется, Ctrl остаётся), `menu_key`, `key_window_ms`, `menu_timeout`, `source` (для `runtime.lua`, каталог репозитория, по умолчанию `/repo`). **`de.conf`:** `boot` путь к загрузчику DE.
- **Загрузчик** вызывается как `loadfile(path)(ctx)`; `ctx = {caps: {pixel, color}, mode: "safe"|nil (выбор в меню), menu: bool, boot_dir, conf_path}`. Возврат: `nil` (питание уже выключено), `"reboot"`, `"craftos"` либо `"recovery", причина` (этап 1 откроет восстановление). Исключение в загрузчике тоже ведёт в восстановление с текстом ошибки. Загрузчик не должен пользоваться `sleep`/`os.pullEvent`, только `pullEventRaw` (иначе Ctrl+T бросит «Terminated»; это тоже попадёт в восстановление, но лучше не провоцировать).
- **`rescue.lua`**: аргументы `reason`, `gate`. Если нет `users.conf`, открыто. Иначе пароль проверяет `runtime.lua` (`recovery_login`: три попытки); нет runtime или проверка упала: **заперто** (перезагрузка через 3 с). После пароля меню: оболочка CraftOS, перезагрузка, выключение; при `gate` сразу `"craftos"`. Если `rescue.lua` отсутствует, а `users.conf` есть, этап 1 тоже запирает (нажатие клавиши перезагружает); без `users.conf` отдаёт CraftOS, чтобы систему можно было установить.
- **`runtime.lua`** это единственное место, знающее, откуда берётся код системы. Сейчас разработческий: исходники репозитория (`source`), компиляция Cubic на лету. В установленной системе (шаг 9, D187) заменяется вариантом с готовым Lua; интерфейс тот же: `import(имя)`, `recovery_login(console, {root})`.
- Меню этапа 1 рисуется текстом; пиксельное меню возможно позже силами DE (`ctx.caps.pixel`).

## Порядок загрузки

1. **Журнал загрузок.** `boot.state` помечает загрузку «начата» (`pending`). Файл `/cubeos/var/boot.state`.
2. **Режим.** По журналу выбирается обычная, безопасная или восстановление (ниже).
3. **Настройки** `/cubeos/sys/cfg/boot.conf` (JSON5): `autologin`, `lang`, `de`, `elevate_ms`, `rounds`, `title`.
4. **Пользователи** из `sys/cfg/users.conf`, пароли из `sys/sec/shadow.lock`, администраторы из `sys/sec/sudoers.lock`.
5. **Ядро** и менеджер сессий. В режиме восстановления ядро не запускается.
6. **Процесс `init`** (от имени `system`) запускает службы из `/cubeos/sys/services/*.conf` по зависимостям и ждёт готовности каждой.
7. **Процесс `login`** (с интерфейсом) ждёт завершения `init`, **снимает отметку «загрузка не закончена»**, показывает вход, после входа запускает оболочку сессии, ждёт её завершения и закрывает сессию; потом снова показывает вход.
8. Выключение или перезагрузка с экрана входа: сессии закрываются, службы останавливаются (просьба завершиться, через 3 с принудительно), загрузка помечается корректно завершённой, вызывается `power.shutdown` или `power.reboot`.

## Режимы

| Режим | Когда | Что происходит |
|---|---|---|
| обычный | прошлая загрузка дошла до входа | всё запускается |
| безопасный | одна подряд незавершённая загрузка | службы с `safe: false` не запускаются |
| восстановление | две подряд незавершённые загрузки или Ctrl при старте | ядро не стартует; стартовый файл проверяет пароль администратора (`boot.recovery_login`, три попытки; без учётных записей открыт) и открывает чистый CraftOS-шелл |

## Пользователи и пароли

- Запись пользователя: `name`, `display` (подпись, можно по-русски), `roles` (`user`, `guest`, ...), `groups`, `color`, `temp` (гость). Имя проверяется как имя в CFS (кириллица можно), без учёта регистра.
- Пароль: PBKDF2-HMAC-SHA256, запись `pbkdf2-sha256$раунды$соль$хэш` в `shadow.lock` (читает только система). Число раундов в `boot.conf` (`rounds`, по умолчанию 1000, около секунды в игре). Нет записи в shadow: пользователь без пароля.
- Соль: из времени, счётчиков и `math.random` (в CC нет системного источника случайных чисел).
- После трёх неудач подряд вход замедляется: пауза 5 с, дальше вдвое, не больше минуты; во время паузы даже верный пароль отклоняется («locked»).
- Администраторы это список в `sudoers.lock`; обычный вход не даёт прав администратора.

## Сессии

Сессия это вход пользователя: субъект CFS, вид файловой системы с `$алиасами`, окружение и процессы.

- `open(имя, пароль)` проверяет пароль, создаёт профиль `/cubeos/users/<имя>/{home/{documents,pictures,videos,projects},apps,cache,cfg,data,desktop,trash}`, если его нет.
- **Гость** (`temp: true`) получает временный профиль `users/<имя>-<номер сессии>`, который удаляется при закрытии сессии.
- Несколько сессий одновременно, активна одна (`switch`). Закрытие сессии завершает её процессы.
- **Повышение прав** (`elevate`): пароль пользователя и членство в `sudoers.lock`; даёт роль `admin` на `elevate_ms` (по умолчанию 5 минут); процессы, запущенные после этого, получают права администратора. `drop_elevation` снимает досрочно. Диалог пароля показывает только ядро (оболочка вызывает `elevate`).
- Блокировка (`lock`/`unlock`): снимает повышение, запрещает запуск процессов, разблокировка по паролю.
- Процессы сессии запускаются с субъектом пользователя и его видом файловой системы (`sys.view()`).

## Службы

Манифест в `/cubeos/sys/services/<имя>.conf` (JSON5): `name`, `module` (модуль с `main(sys, args)`), `requires`, `after`, `restart` (`on-failure`, `always`, `never`), `max_restarts`, `restart_delay`, `ready` (`register` или `immediate`), `timeout`, `enabled`, `safe`.

- Порядок запуска по зависимостям; службы с нескольким одинаковым уровнем идут по имени; цикл и неизвестная зависимость попадают в журнал.
- Готовность: служба вызывает `sys.register(имя)`.
- Если нужная служба не запустилась, зависимая получает состояние `blocked`.
- Каждую службу ведёт надзиратель (процесс `svc-<имя>`): перезапуск по правилам, остановка при выключении.
- Состояния: `stopped`, `starting`, `running`, `failed`, `blocked`, `disabled`.

## Вход

Пока нет библиотеки интерфейса, вход текстовый (`TextGreeter` поверх `console`): список пользователей, ввод номера или имени, пароль звёздочками; при первой загрузке предлагается создать первого администратора. Тексты английские (D135). `console` это интерфейс (`write`, `write_line`, `clear`, `read_line(подсказка, скрыть)`) с реализациями `TermConsole` (настоящий терминал CC) и `ScriptedConsole` (тесты). Плиточный экран входа придёт с библиотекой интерфейса и займёт место `TextGreeter`.

## Использование

```cubic
b = boot.new({fsys: fsys, console: console, import: loader.import, shell: (session) => program,
              kernel: {pull: cckernel.pull, rt: cubic.rt, cubic: cubic}, power: {shutdown: ..., reboot: ...}})
system = b:start()
if system.mode == "recovery": ...         # проверить boot.recovery_login и открыть чистый CraftOS
else: system.kernel:run()
```

Эталон для настоящего CC: `game/boot_demo.lua` (папка данных `/cubeos-demo`, Ctrl при старте для восстановления).
