# Пакетный менеджер

Менеджер называется `stew` (команда `stew`, демон `stewd`), официальный каталог и магазин называются Cobble («Cobble Store»). Магазин приложений это только окно к менеджеру: GUI, CLI и системные вызовы (двойной клик по `.cpk`, «открыть с помощью») используют один и тот же API.

## Слои

1. **Ядро** (сервис `stewd`). Ничего не рисует. Планирует, скачивает, проверяет, ставит, обновляет, удаляет, ведёт базу установленных пакетов. Отдаёт API и события прогресса.
2. **Источники.** Каталоги пакетов разного происхождения (официальный, сообщества, личные, диск, rednet).
3. **Клиенты.** CLI, приложение «Магазин», системные вызовы.

## Установка только целиком

Установка либо проходит полностью, либо ничего не меняется. Частично установленного пакета не бывает.

1. **План.** Разрешаются зависимости, считается место (см. ниже). Ошибки и нехватка места обнаруживаются до скачивания.
2. **Скачивание** в промежуточный каталог `/cubeos/var/stew/staging/<txn>`. Каждый файл сверяется с размером и хэшем из каталога.
3. **Проверка.** Пакеты распаковываются в промежуточный каталог, проверяются манифесты, совместимость, конфликты. Разрешения показываются пользователю.
4. **Журнал.** Перед фиксацией пишется журнал транзакции (список операций: что поставить, что заменить, что удалить).
5. **Фиксация.** Файлы переносятся на место (`fs.move`), заменяемые файлы старых версий уходят в `/cubeos/var/stew/trash/<txn>`. После успеха база установленных обновляется, корзина транзакции очищается.
6. **Восстановление.** Если питание пропало (чанк выгрузился, компьютер выключили) посреди фиксации, при следующей загрузке сервис читает журнал и откатывает недоделанную транзакцию из корзины. Транзакция без записи «готово» считается неудачной.

Отмена на любом этапе до фиксации просто удаляет промежуточный каталог.

## Запрос «сколько места нужно»

Перед скачиванием менеджер отвечает на вопрос, влезет ли пакет, и показывает расчёт:

```
stew plan chess
```

Результат:

| Строка | Смысл |
|---|---|
| к установке | сам пакет и его зависимости, которых ещё нет (или нужна версия новее) |
| уже стоит | зависимости, уже удовлетворяющие требованию (места не занимают) |
| скачать | сумма размеров архивов `.cpk`, которые реально нужно скачать |
| займёт после установки | сумма размеров распакованных файлов новых пакетов минус то, что освободится при замене старых версий |
| пик во время установки | промежуточные файлы: скачанное + распакованное в staging + ещё не удалённые старые версии |
| свободно сейчас | свободное место на целевом диске |
| запас | резерв, который не трогаем (настройка, по умолчанию max(5% диска, 20 КБ)) |
| вердикт | `влезает` или `не хватает N байт`; при нехватке предлагает, что можно удалить (неиспользуемые зависимости, кэш, корзина) |

Правила расчёта:

- считаются только пакеты, которых нет или версия которых не подходит; установленные зависимости не учитываются;
- обновление пакета вычитает размер заменяемой версии из итога (но для пика она ещё занята);
- общие зависимости нескольких пакетов в одном плане считаются один раз;
- пиковое место проверяется отдельно от итогового: пакет может влезать на диск, но не пройти установку из-за промежуточных файлов, в этом случае менеджер сообщает пик и предлагает установку по одному пакету или очистку кэша;
- диск назначения выбирается по пакету (системные пакеты идут на системный диск, пользовательские на домашний диск пользователя).

Размеры берутся из каталога без скачивания самих пакетов: в записи каждой версии есть `size` (архив) и `installed_size` (распакованный объём), оба проверяются при загрузке. Если источник умный (свой сервер на rednet, прокси), он может принять список установленного и посчитать план сам (`plan`); обычный статический каталог на GitHub обходится без этого, расчёт делает клиент.

## Источники

Список источников в `sources.json5` (системный и пользовательский):

```json5
{
  sources: [
    { name: "cobble", kind: "github", url: "cubeos/cobble", trust: "official" },
    { name: "friend", kind: "http", url: "https://example.com/cubeos/index.json5", trust: "user" },
    { name: "disk", kind: "path", url: "/disk/packages", trust: "user" },
  ],
}
```

Виды (`kind`): `github`, `http`, `pastebin`, `gist`, `rednet`, `path` (диск, дискета, другая папка). Все ведут к одному формату каталога `index.json5`.

### Сторонние источники (как AUR)

Установка из любых источников разрешена. Чтобы это не превратилось в дыру:

- **Уровни доверия.** `official` (каталог проекта), `community` (подключён, проверен сообществом), `user` (добавил сам пользователь), `adhoc` (одноразовая установка по ссылке). Уровень виден в интерфейсе и в плане.
- **Подключение источника.** Первый раз требует подтверждения: показывается адрес, что в нём (число пакетов), что источник не проверен.
- **Разовая установка** по ссылке или id Pastebin: `stew install https://...` или `stew install pastebin:XXXXXXXX` ставит пакет без добавления источника, с предупреждением и показом разрешений.
- **Рецепты.** Источник может не хранить готовые `.cpk`, а хранить рецепт (`recipe.json5`): манифест и список файлов с адресами и хэшами. Менеджер сам скачивает файлы, проверяет их хэши и собирает `.cpk` локально. Так пакет можно описать, не выкладывая архив, и обновления проверяются построчно.
- **Ограничения по доверию.** Пакеты из `user`/`adhoc` источников не получают системные разрешения без отдельного подтверждения; во время установки показывается, что именно они просят.
- **Обновления.** Если в новой версии добавлены разрешения или поменялся источник, обновление не ставится молча, пользователю показывается разница.
- **Подмена.** Имя пакета привязано к источнику, из которого он поставлен. Источник с таким же именем не может подменить установленный пакет без явного подтверждения.
- **Хэши.** Каталог должен задавать хэш каждого файла. Каталоги получаются по `https`. Подписи (ed25519) на чистом Lua слишком медленны, поэтому на старте только хэши; позже можно добавить подписи каталогов.

### Готовые каталоги, которые стоит подключить

- **PineStore** (существующий каталог программ для CC): отдельный вид источника `pinestore`, уровень доверия `community`. Нужен адаптер, который переводит его записи в формат каталога stew; пакеты из него ставятся с ограниченными правами, как и все чужие.
- **Порт Doom для CC** (открытый): один из первых пакетов Cobble или рецепт во внешнем источнике; проверка лицензии и условий распространения перед включением в официальный каталог.

## Команды

| Команда | Действие |
|---|---|
| `stew plan <имя>` | расчёт места и зависимостей, ничего не меняет |
| `stew install <имя>` | то же, что `plan`, затем целиковая установка с подтверждением |
| `stew remove <имя>` | удаление (с зависимостями, которые больше никому не нужны, по запросу) |
| `stew update [имя]` | обновление: сначала план, потом транзакция |
| `stew search <запрос>` | поиск по подключённым источникам |
| `stew info <имя>` | версия, размер, зависимости, разрешения, источник и уровень доверия |
| `stew list` | установленное |
| `stew source add/remove/list` | управление источниками |
| `stew pin <имя>` | запретить обновление |
| `stew rollback <имя>` | вернуть предыдущую версию, если она ещё в корзине |
| `stew clean` | очистить кэш, корзину, неиспользуемые зависимости |
| `stew verify` | проверить хэши установленных файлов |

Каналы: `stable`, `beta`, `dev`; указываются в источнике или у пакета.
Автономная работа: кэш каталога, установка из файла `.cpk`, диска и дискеты без сети.

## Запись в каталоге

```json5
{
  name: "chess",
  versions: {
    "1.2.0": {
      url: "https://.../chess-1.2.0.cpk",
      sha256: "…",
      size: 18432,              // архив
      installed_size: 41200,    // распакованный объём
      need: ["cubic-ui >= 1.0"],
      want: ["chess-engine"],
      conflicts: [],
      permissions: ["storage.read", "network.rednet"],
    },
  },
}
```

## Что остаётся уточнить

- Формат рецепта и где он хранится рядом с каталогом.
- Размер резерва по умолчанию (измерим на реальном диске).
- Можно ли держать несколько версий одного пакета рядом (для игр с общими сохранениями) или только одну.
