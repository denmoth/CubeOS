# CGL: Cube Graphics Library

Графическая библиотека CubeOS, на которой строятся библиотека интерфейса, рабочий стол и игры. Код: `lib/cgl/`. Тесты: `tests/cases/lib_cgl_*.cub`. Демонстрация: `examples/cgl_demo.cub` с запуском `game/cgl_demo.lua`. Решения D160–D167 в [08-decisions-log.md](../08-decisions-log.md).

Библиотека написана с нуля. Идеи (поверхность в памяти, телетекстные символы для обычного терминала, разность кадров) общие для всей области; чужой код не копировался: у CCGL нет лицензии, а значит, права на него не переданы (D160).

## Модули

| Модуль | Что делает |
|---|---|
| `cgl` | `cgl.open()` выбирает вывод и возвращает `Screen` (поверхность, показ кадра, цикл кадров) |
| `cgl.surface` | `Surface`: пиксели-номера цветов, фигуры, текст, копирование, отсечение, сдвиг |
| `cgl.color` | палитры на 256 цветов, ближайший цвет, градиенты и ломаные ступени, HSV, дизеринг Байера |
| `cgl.graphics` | вывод в пиксельный режим CC: Graphics (режим 2 на 256 цветов или режим 1 на 16) |
| `cgl.teletext` | вывод на обычный цветной терминал символами 128..159 (2x3 пикселя на клетку) |
| `cgl.mirror` | одна картинка на несколько выводов (мониторов) сразу |
| `cgl.quant` | перевод цветов поверхности в 16 цветов терминала, с дизерингом |
| `cgl.anim` | кривые плавности, твины, последовательности, пружина |
| `cgl.cimg` | формат изображений `.cimg` (палитра, прозрачность, сжатие) |
| `cgl.fx` | плазма, звёздное поле, частицы |
| `cgl.g3d` | сетки (куб, пирамида, сфера, тор), проволока, закрашенные грани с освещением |

## Цвет и палитра

Цвет в CGL это номер в палитре 0..255. Первые 16 номеров совпадают с 16 цветами CC (номер это номер бита: `colors.white` это 0, `colors.black` это 15), дальше куб 6x6x6 (16..231) и 24 серых (232..255). Прозрачный пиксель в спрайте это `CLEAR` (-1). Палитру можно менять (`palette:set(i, r, g, b)`): в пиксельном режиме 2 она уходит в терминал целиком через `term.setPaletteColor`.

```cubic
p = color.default_palette()
p:nearest(255, 128, 0)                                             # ближайший номер
sky = p:ramp([[6, 8, 36], [150, 50, 120], [255, 210, 120]], 30)    # 30 ступеней через три цвета
rainbow = p:ramp(color.rainbow_stops(12), 48)
```

## Поверхность

`surface.new(w, h, fill)`. Координаты с нуля, как в `term.drawPixels`. Все операции учитывают область отсечения (`push_clip`/`pop_clip`) и сдвиг начала координат (`push_origin`/`pop_origin`).

| Группа | Методы |
|---|---|
| точки и заливка | `set`, `get`, `clear`, `flood_fill`, `fill_gradient` (по вертикали или горизонтали), `fill_pattern` (узор 8x8) |
| фигуры | `line` (с толщиной), `hline`, `vline`, `rect` (с толщиной), `fill_rect`, `circle`, `ellipse`, `round_rect`, `triangle`, `polygon` (залитый и контур) |
| копирование | `blit` (часть источника, зеркала, масштаб по осям, прозрачность, замена цветов `map`), `crop`, `rotate90`, `nine_patch` |
| текст | `text(font, x, y, строка, цвет, {scale, spacing, bold, italic, underline, shadow, outline})`, `surface.measure`, `wrap`, `ellipsize` |
| отладка | `to_text`, `equals`, `checksum`, `copy` |

Текст рисуется шрифтами `lib/font.cub` ([font-format.md](font-format.md)); для кириллицы основной шрифт Monocraft 6x9.

## Вывод и кадр

```cubic
import cgl
screen = cgl.open()                   # пиксели, если есть CC: Graphics; иначе телетекст
s = screen.surface                    # размер экрана в пикселях: 306x171 (пиксели) или 102x57 (телетекст) на 51x19 клеток
# ... рисуем в s ...
screen:present()                      # показать кадр
screen:run((dt, frame) => ..., {fps: 20, on_event: (ev, a, b, c) => ...})   # цикл кадров
screen:close()
```

### Изменённая область

Поверхность запоминает прямоугольник, в котором что-то менялось с прошлого показа (`dx0..dx1`, `dy0..dy1`), а дисплей сравнивает кадры только внутри него. Если ничего не менялось, `present` не делает ничего (0 мс), если поменялась одна точка, сканируется одна точка. Все методы поверхности ведут этот прямоугольник сами; код, пишущий прямо в `surface.px`, должен вызвать `s:touch()` (вся поверхность) или `s:mark(x0, y0, x1, y1)`. Замер в игре на мониторе 984x729 до этого: любое изменение стоило 160 мс, потому что сканировались все 718 тысяч пикселей.

Один дисплей на одну поверхность: дисплей забирает у поверхности список изменений. Чтобы показать картинку на нескольких мониторах, есть `cgl.open({term: монитор1, mirror: [монитор2, монитор3]})` (`cgl.mirror`): поверхность одна, каждый вывод получает все изменения. Мониторы должны быть одного размера и масштаба текста.

### Анимация на больших экранах

На мониторе в 700 тысяч пикселей перерисовывать фон каждый кадр нельзя (одна заливка экрана 50 мс). Приём: фон рисуется один раз и запоминается (`bg = s:copy()`), а каждый кадр восстанавливаются только движущиеся места (`s:restore(bg, x, y, w, h)`) и рисуются поверх. Поверхность сама ведёт прямоугольник изменений, так что показ тоже затрагивает только их. Для эффектов, которые меняют каждый пиксель (плазма, 3D), считают в малом размере и растягивают в окно не больше ~90 тысяч пикселей. Пример: сцены в `examples/cgl_demo.cub`. `fx.Starfield` умеет стирать свои звёзды (`erase(s, bg)`).

### CC: Graphics (`cgl.graphics`)

Режим 2 (по умолчанию): номера палитры идут в терминал как есть, палитра загружается при `open`. Режим 1: 16 цветов CC, остальные подбираются `cgl.quant`, можно включить дизеринг. Кадр сравнивается с прошлым построчно; изменения собираются в прямоугольники (соседние строки сливаются, если лишняя площадь не растёт больше чем на половину), на прямоугольник один вызов `drawPixels`. Вывод заключён в `setFrozen`, чтобы экран не мигал. Если ничего не изменилось, вызовов нет.

### Телетекст (`cgl.teletext`)

Для каждой клетки из шести пикселей выбираются два самых частых цвета (из 16), остальные уходят к ближайшему из двух; правый нижний пиксель символа по правилам CC всегда фоновый, поэтому при нужде цвета меняются местами, а рисунок инвертируется. Изменившиеся клетки одной строки уходят одним `term.blit`. Дизеринг по умолчанию включён: цвета, которых нет среди 16, смешиваются из лучшей пары по матрице Байера 4x4.

События мыши: в пиксельном режиме координаты уже в пикселях, в телетексте это клетки; `screen:to_pixel(x, y)` приводит оба случая к пикселю поверхности.

## Анимация

Анимация палитры: `screen:set_colors([[номер, r, g, b], ...])`. На пиксельном режиме 2 это только вызовы `term.setPaletteColor`, кадр не перерисовывается и не отправляется (пример: сцена «Интро» в `examples/cgl_demo.cub`, волна проявления логотипа). На других выводах кадр пересчитывается.

`anim.ease("out_bounce", t)`: 31 кривая (`linear` и `in_`, `out_`, `in_out_` для quad, cubic, quart, sine, expo, circ, back, elastic, bounce). `anim.tween({from, to, time, ease, delay, repeat, yoyo, on_update, on_done})` работает с числами и списками чисел. `sequence`, `parallel`, `wait`, `call` собирают сценарии; `Animator:update(dt)` продвигает всё и убирает законченное; `anim.spring` догоняет цель без фиксированного времени. Часов внутри нет: всё считается от `dt`, поведение детерминировано.

## Изображения

Файл `.cimg`: заголовок `CIM1`, размеры, флаги (прозрачность, своя палитра), необязательная палитра и блок `lib/compress` с номерами цветов (и маской прозрачности). `cimg.encode/decode` работают со строками, `cimg.write_file/read_file` с файлами. `tools/png2cimg.py in.png out.cimg [--size WxH] [--palette default|adaptive]` делает файлы из картинок (альфа меньше 128 даёт прозрачность). Пример: `assets/images/cubeos-logo.cimg`.

## Эффекты и трёхмерная графика

`fx.Plasma`, `fx.Starfield`, `fx.Particles` считают целыми числами и таблицами; весь экран считают в малом размере и растягивают `blit(..., {scale: 3})`. `g3d.render(surface, mesh, {rx, ry, rz, z, fov, mode})`: режимы `wire`, `flat` (скрытие обратных граней, дальние раньше, освещение по палитровой лесенке `ramp`), `points`.
