# 02. Файловая система

Статус: **зафиксировано** (структура принята 2026-10-13/14). Детали форматов в [03-file-formats.md](03-file-formats.md), права в [12-permissions-capabilities.md](12-permissions-capabilities.md).

## Структура

Корень системы `/cubeos`. Концепт структуры предложил автор, мы разделили неизменяемое и изменяемое.

```
/cubeos/
├─ sys/            ТОЛЬКО ЧТЕНИЕ (пишут system/admin через ОС)
│  ├─ boot/        init.lua, kernel.lua
│  ├─ core/        vfs, compositor, netfs (демоны)
│  ├─ drivers/     модули периферии (.driv)
│  ├─ libs/        библиотеки (.clib)
│  ├─ bin/         базовые утилиты
│  ├─ lang/        словари (.lang)
│  ├─ services/    конфиги автозапуска демонов
│  ├─ assets/      fonts/, icons/, boot/
│  ├─ cfg/         users.conf, env.conf, repos.conf, cloud.conf, caps.conf, mods.conf, tags.conf, os-release.conf
│  ├─ recovery/    записи восстановления (.rv)
│  ├─ sec/         shadow.lock, sudoers.lock (закрыта для всех, кроме system)
│  └─ api/         заголовки Cubic (.cuh), необязательный пакет SDK
├─ var/            ИЗМЕНЯЕМОЕ СОСТОЯНИЕ СИСТЕМЫ
│  ├─ log/  db/ (packages.dat, периферия)  cache/  net/ (dns.dat)
├─ shared/         доступно всем пользователям
│  ├─ apps/  games/  data/  projects/  themes/
├─ drives/         диски; дискеты отдельно: drives/floppy/<метка>
├─ hardware/       ВИРТУАЛЬНАЯ: метаданные периферии (тип, имя, сторона, методы), не вызовы
├─ proc/           ВИРТУАЛЬНАЯ: информация о процессах (в памяти)
├─ run/            ВИРТУАЛЬНАЯ: PID-файлы, каналы IPC, сокеты (в памяти)
├─ tmp/            в памяти или чистится при загрузке
└─ users/<имя>/
   ├─ apps/  cache/  cfg/ (cron/, themes/)  data/  desktop/  trash/   служебные, зарезервированы
   ├─ home/        documents/  pictures/  videos/  projects/
   └─ ...          всё остальное принадлежит пользователю и свободно
```

Отличия от исходного концепта:
- Логи, база пакетов, DNS-кеш вынесены из `sys` в `var`, чтобы `sys` была строго только для чтения.
- `proc`, `run`, сокеты виртуальные и лежат в корне, а не в `sys`.
- Ссылки на ядро для восстановления это записи `.rv` в `sys/recovery` (не `.fb`).

### Профиль пользователя

- В `users/<имя>/` лежат служебные папки и свободные файлы пользователя; в `home/` упорядоченные папки.
- Служебные имена на этом уровне **зарезервированы**: `apps`, `cache`, `cfg`, `data`, `desktop`, `trash`, `home`. Нельзя создать свою папку с таким именем.
- `$user` это весь профиль, `$home` это `users/<имя>/home`.

## Шорткаты `$`

Таблица в `sys/cfg/env.conf` (системные) и `users/<имя>/cfg` (пользовательские). Подстановка в строках путей, в шелле и в `import`.

| Алиас | Значение |
|---|---|
| `$sys`, `$var`, `$shared` | `/cubeos/sys`, `/cubeos/var`, `/cubeos/shared` |
| `$apps` | `/cubeos/shared/apps` |
| `$userapps` | `$user/apps` |
| `$user` | `/cubeos/users/<имя>` |
| `$home` | `$user/home` |
| `$docs`, `$pictures`, `$videos`, `$projects` | подпапки `$home` |
| `$desktop`, `$cfg`, `$cache`, `$trash` | подпапки `$user` |
| `$appdata` | `$user/data/<id приложения>` (у каждого приложения свой) |
| `$shareddata` | `/cubeos/shared/data/<id приложения>` |
| `$tmp`, `$mnt` | `/cubeos/tmp`, `/cubeos/drives` |

Правила:
- Алиасы могут ссылаться на другие алиасы, циклы запрещены.
- Весь файл можно экспортировать и восстановить после переустановки.
- Символ `$`: ввод Shift+4 на английской раскладке.

## CFS (Cube File System)

Слой виртуальной файловой системы называется **CFS** (код в `lib/cfs/`). Файловый менеджер (приложение) это отдельная вещь.

### Имена

- Разрешён UTF-8 (в том числе кириллица). Запрещены управляющие символы, `\ : * ? " < > |`, пробел или точка в конце, имена `.` и `..`. Длина имени до 64 байт.
- Имя, начинающееся с точки, **скрыто** (в списках только по запросу).
- Имя, начинающееся с `!`, **важное** (см. ниже).
- Имена, различающиеся только регистром, в одном каталоге запрещены.

### Важные файлы (`!`)

Файл или каталог с именем на `!` (и всё внутри такого каталога) считается важным. Создание, изменение, удаление и переименование требуют прав администратора и дополнительного подтверждения («вы уверены?»). Чтение разрешено по обычным правилам. Подтверждение запрашивает ядро через обработчик (`confirm`); без обработчика операция отклоняется. Роль `system` подтверждения не требует.

### Корзина

Удаление в личных папках уходит в корзину пользователя (`$trash`, по умолчанию `users/<имя>/trash`). Расположение корзины (в том числе другой диск) и её размер настраиваются. Удалить минуя корзину можно явно (`permanent`). В `tmp`, `sys` и в самой корзине удаление окончательное. Переполнение корзины вытесняет самое старое.

### Блокировки, события, tmp

- Блокировки рекомендательные (по запросу): `lock`/`unlock`, система не принуждает.
- Изменения файлов порождают уведомления (`watch(путь, функция)` и событие `cfs_change`).
- `tmp` лежит в памяти с лимитом размера; очистка по расписанию (возраст файлов, интервал) настраивается, есть команда `clean`.

### Права и вид процесса

- Правила по префиксу пути, только разрешающие (`allow`), по умолчанию запрещено; побеждает самое конкретное правило, роль `system` ничем не ограничена.
- У процесса виртуальный корень: приложение видит только разрешённые пути (`binds`), реальные пути скрыты.

### Совместимость

Программам без API CubeOS подставляется замещённый `fs` (слой совместимости поверх CFS).

Конвейер запроса:
1. Подстановка `$alias`.
2. Нормализация (`..`, двойные слэши).
3. Разворот симлинков `.sym` (глубина до 16).
4. Поиск точки монтирования по самому длинному префиксу.
5. Проверка прав (после разворота ссылок, чтобы нельзя было обойти защиту ссылкой).
6. Операция провайдера.

Провайдеры: реальный каталог, диск и дискета, память (`tmp`, `proc`, `run`), смонтированный `.cpk`/`.cbx` (только чтение, без распаковки), сетевой том (rednet), облачные заглушки `.cloud`, зеркало облака.

Общее:
- Запись атомарная (во временный файл, затем `move`).
- Дескрипторы закрываются при смерти процесса; общие файлы имеют блокировки.
- У каждого процесса свой вид файловой системы, ограниченный его разрешениями.
- Имена, различающиеся только регистром, в одном каталоге запрещены (на Windows-хосте файловая система может быть регистронезависимой **(проверить)**).
- `fs` CC: Tweaked симлинки не поддерживает, поэтому реализуем в VFS. Legacy-процессам подставляется заменённый `fs`.

## Симлинки и ярлыки

- **Симлинк `.sym`:** маленький файл с целевым путём. VFS показывает как `имя` с типом "ссылка". Поиск `foo`: если не найден, проверяем `foo.sym` (одна лишняя проверка только при промахе). `delete` на ссылке удаляет ссылку. Битая ссылка даёт понятную ошибку. В режиме восстановления (чистый CraftOS) видны как маленькие файлы.
- **Ярлык `.link`:** файл для оболочки (цель, иконка, аргументы), например на рабочем столе. Отдельная сущность, VFS его не разворачивает.

## Диски и дискеты

- Диски монтируются автоматически по `disk_insert` в `drives/<метка или ID>`. Привязка к ID диска (`disk.getID`, `disk.getLabel`), а не к стороне дисковода.
- Безопасное извлечение: пока открыты файлы, "занято"; при извлечении данные сбрасываются.
- **Дискеты отдельно:** `drives/floppy/<метка>`. Маленький съёмный носитель (около 125 КБ **(проверить)**) для переноса и установки. Загрузочная дискета с установщиком и восстановлением.
- **Код с носителей никогда не запускается сам**, только по запросу с показом источника и разрешений.
- Дополнительные диски служат расширением места (перенос приложений и `$appdata`).
- Мод `harddisks` и подобные поддерживаются драйвером, система обязана работать без них.

## Облачные файлы

Заглушки `.cloud` (формат в [03-file-formats.md](03-file-formats.md)). Файл-пустышка с источником (Pastebin, Gist, rednet-сервер, URL); VFS докачивает содержимое при открытии и кладёт в кеш (`$cache`, `var/cache`). Кеш ограничен квотой, вытесняется самое старое. Для кода обязателен хэш.

## Права (кратко)

Подробно в [12-permissions-capabilities.md](12-permissions-capabilities.md).

| Область | Чтение | Запись |
|---|---|---|
| `sys` | все | только system/admin через ОС (кроме `sec`: только system) |
| `var` | система, админы | система |
| `shared` | все пользователи | админы (в `projects` участники группы) |
| `users/<имя>` | владелец (админы тоже, как доверенные) | владелец |
| `tmp` | все | все |

## Место

Диск обычно 1 МБ, поэтому:
- Резерв не менее около 32 КБ для обновлений и восстановления.
- Предупреждение при 90%, при нехватке приложение получает понятную ошибку.
- Приложения хранятся как смонтированные `.cpk` (сжатые), без распаковки.
- Облачные заглушки "установлено, но не занимает место".
- Квоты по пользователям и приложениям.
