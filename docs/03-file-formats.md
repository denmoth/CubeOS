# 03. Форматы файлов

## Расширения

| Расширение | Что это | Заметки |
|---|---|---|
| `.lua` | Lua-код | как в CraftOS |
| `.cub` | Исходник Cubic | компилируется в `.lua` |
| `.cpk` | **C**ube **P**ac**K**age, пакет приложения | аналог APK |
| `.stp` | **S**e**T**u**P**, установщик | самораспаковывающийся |
| `.json5` | Конфиги и данные (JSON5) | комментарии, запятая в конце |
| `.json` | Обычный JSON | для обмена |
| `.fnt` | Растровый шрифт | формат определить |
| `.img` | Изображение | пиксели + палитра, RLE |
| `.thm` | Тема оформления | JSON5 |
| `.nft`, `.nfp` | Форматы CC | поддерживаются как есть |
| `.dfpwm` | Звук | CC |

Нет `.cbc`: компилятор выдаёт обычный Lua, байткода нет.

## JSON5 (конфиги)

Используем стандартный **JSON5**: комментарии (`//`, `/* */`), запятая в конце, ключи без кавычек, одинарные кавычки. Свой формат не вводим: есть спецификация и готовая подсветка в редакторах.

### Запись значений без потери комментариев

Парсер запоминает позиции значений в тексте. При изменении значения (например, из настроек) заменяется **только текст значения**, остальной файл не трогается. Проект: общий модуль `json5` с функцией `patch(text, path, value)`.

### Дефолты и переопределения

- Дефолты в системном файле (read-only).
- Пользовательские изменения в отдельном файле-переопределении (`user.json5`).
- Это облегчает обновления и откат.

## `.cpk` (пакет приложения)

Содержит манифест и дерево файлов. Манифест (`manifest.json5`), черновик:

```json5
{
  id: "snake",
  name: "Змейка",
  version: "1.0.0",            // SemVer
  cubic: ">=0.1",              // версия языка
  ui: "both",                  // window | text | both
  permissions: ["fs.appdata", "gfx"],
  depends: [],
  associations: [],
  entry: "main.lua",
  icon: "icon.img",
}
```

Детали (поля, подпись, хэши) **(определить)**. Файлы читаются и пишутся в бинарном режиме (`"rb"`/`"wb"`).

## `.stp` (установщик)

Отличие от `.cpk`: `.cpk` это приложение, `.stp` это **установщик**. Содержит:

- один или несколько `.cpk`, обычные файлы, патчи системы;
- манифест с шагами установки (куда что положить, через `$`-пути);
- регистрацию ассоциаций, ярлыков, разрешений;
- пре- и пост-скрипты;
- лицензию и опции выбора компонентов;
- запись для чистого удаления.

Главное применение: **установка самой CubeOS на чистый CraftOS одной командой**. Поэтому заголовок `.stp` это самодостаточный Lua-загрузчик, работающий без CubeOS. Мастер установки существует в оконном и текстовом режимах.

Технические вопросы **(определить)**: сжатие на чистом Lua (LZW или LZ4), CRC32, бинарно-безопасное кодирование (base64 раздувает на около 33%), лимиты Pastebin при раздаче.

## Встроенная утилита создания установщиков

Часть ОС: `stp build <папка> <файл.stp>`, мастер сборки в GUI. Создаёт установщик по манифесту.
