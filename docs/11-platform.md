# 11. Платформа: дистрибутивы, DE, версии, режим совместимости

## Дистрибутивы

- Дистрибутив это пакет `kind: "distro"`: набор пакетов, готовые настройки, тема, логотип, список приложений по умолчанию.
- Может включать одну или несколько DE (`includes`) и назначать одну по умолчанию.
- Собирается встроенным конструктором `.stp`.
- Информация о дистрибутиве: `sys/cfg/os-release.conf`.

## DE (окружения)

- Пакет `kind: "de"`: оболочка, панель, лаунчер, оформление.
- Выбор DE на экране входа (сессия), как в Linux.
- Режимы отображения `window` и `text` это не отдельные DE, а настройка внутри DE. DE объявляет, какие режимы поддерживает (`modes: ["window", "text"]`), переключение в её настройках.
- Условие: композитор и API оболочки это **стабильный версионируемый контракт**, иначе чужие DE ломаются при каждом обновлении.

## Версии ОС

- Каждая версия ОС хранится отдельно как пакет `kind: "os"` в релизах (например, GitHub Releases).
- Дистрибутив фиксирует нужную версию (`cubeos: "0.4.x"`). Установщик дистрибутива скачивает эту версию ОС вместе с ним.
- Любую старую версию можно поставить вручную; откат это установка предыдущего релиза.

## Расслоение API

- `cube.*`: базовое, стабильное API ОС.
- `ext.<id>.*`: расширения дистрибутива или DE.

Это правило обязательно: оно делает возможным режим совместимости и стабильность.

## Требования приложения к платформе

В манифесте (см. [03-file-formats.md](03-file-formats.md)) на двух осях, дистрибутив и DE, есть списки `supports` и `unsupported`. Если не указано, считается, что поддерживается везде.

## Режим совместимости

Если текущий дистрибутив или DE не поддерживается приложением, оно запускается в режиме совместимости:
- расширения `ext.*` скрыты;
- тема и теги приводятся к базовым;
- `cube.platform` сообщает "cubeos / base".

Приложение уверено, что работает на чистой CubeOS. Реализация это отдельный профиль процесса (урезанная таблица API), не виртуальная машина.

Приложение может узнать о режиме: `cube.platform.compat()` возвращает признак и причину. Реальные имена дистрибутива и DE скрыты по умолчанию.

## Периферия и моды

- ОС ведёт каталог известной периферии (типы и методы из `caps.conf`, включая никогда не подключавшуюся) и журнал подключённой на этой машине (имя, тип, сторона, первое и последнее подключение), хранится в `var/db`.
- Возможность имеет два состояния: **доступна сейчас** (периферия достижима, методы на месте) и **известна** (видели раньше или отмечена вручную).
- CC не умеет перечислять установленные моды. Наличие мода можно определить только по периферии или API, поэтому `mod:` это синоним, разворачиваемый через `mods.conf`.
- Проверка возможностей идёт по методам, а не по типу периферии.
