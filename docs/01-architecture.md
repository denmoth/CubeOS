# 01. Архитектура

## Слои (снизу вверх)

```
CraftOS (BIOS, shell, fs, term)    <- базовый терминал, не меняем
└─ Загрузчик      (startup.lua, recovery)
   └─ Ядро        (процессы-корутины, события, планировщик, IPC)
      └─ HAL      (gfx, audio, net, storage, input)
         └─ Сервисы (wm, fontd, audiod, netd, stewd, notifyd, clipboard, vfs)
            └─ API пользователя (`cube.*`)
               └─ Приложения
```

## Загрузка

- `startup.lua` запускает загрузчик CubeOS.
- **Recovery:** зажатый Ctrl при старте или два падения подряд ведут в чистый CraftOS-шелл. Систему невозможно "убить" полностью.
- Режим при старте: оконный или текстовый (см. [04-ui-graphics-fonts.md](04-ui-graphics-fonts.md)).

## Ядро

- Процессы это корутины. У каждого своё окружение (`setfenv`/`load` с `env`), своя таблица окон, свои разрешения.
- Маршрутизация событий: клавиатура и мышь идут в окно в фокусе, остальные события (rednet, таймеры) по подпискам.
- Планировщик кооперативный (`yield`). Для защиты от завершения CC по таймауту (`too long without yielding`) компилятор Cubic может **автоматически вставлять yield** в тяжёлые циклы (опция).
- IPC: сообщения между процессами и события-каналы.
- **В отличие от прежних версий:** нет `_G.kernel`, `_G.WindowManager`. Всё через `import`.

## Защита встроенных имён

1. **Компилятор:** присвоение встроенного имени или импортированного модуля это ошибка (`cannot assign to builtin 'print'`). Локальная переменная или параметр с таким именем это предупреждение (в `strict` ошибка).
2. **Рантайм:** окружение процесса это прокси с `__newindex`, запрещающим перезапись защищённых имён. Модули (`fs`, `ui`, ...) доступны только на чтение.
3. **Явное переопределение:** синтаксис `override print = my_print`. В песочнице требует разрешения. Нужно для логирования и тестов.
4. Константы: `const X = 1`.

## Разрешения и песочница

Подробности в [12-permissions-capabilities.md](12-permissions-capabilities.md). Дистрибутивы, DE и режим совместимости: [11-platform.md](11-platform.md).

- Приложение объявляет разрешения в манифесте (`fs.read`, `fs.write`, `net.http`, `periph.*`, ...).
- Пользователь видит список при установке и может отозвать в настройках.
- Файловый доступ ограничен: свой `$appdata`, `$temp`, явно разрешённые пути.
- `Permissions.request` для разрешений "по требованию".

## HAL (слой драйверов)

Приложения не проверяют наличие аддона, они спрашивают возможности:

```
gfx.caps()  -> { pixel = true, truecolor = true, accel = true, ... }
audio.caps()
periph.has("chatBox")
```

Бэкенды графики:

| Бэкенд | Условие | Возможности |
|---|---|---|
| `cc-graphics` | аддон есть | пиксели, спрайты |
| `teletext` | нет аддона | субпиксели 2x3 на символ (символы 128-159) |
| `text` | минимум (pocket, ограниченный терминал) | `term`, 16 цветов |

## Процессы и legacy

- Обычные `.lua` и CraftOS-программы запускаются как legacy-процесс: `term` перенаправлен в окно, `fs` заменён VFS-обёрткой (иначе симлинки не видны).
- Из legacy недоступны: песочница в полном объёме, `import`.

## Бюджет места

Диск компьютера 1 МБ (по умолчанию; на сервере может быть иначе). Система не должна занимать его целиком.

- Минимальная установка (ядро, VFS, шелл, редактор, менеджер пакетов): **цель не более около 250 КБ** (предложение, подтвердить измерением).
- Всё остальное устанавливается по требованию: игры, словари Wordle, шрифты, темы, языки.
- Приложения в `.cpk` хранятся сжатыми и/или минифицированными.
- Данные пользователя можно выносить на внешние диски (`$mnt`) и в облако.
- В диспетчере задач и настройках виден расход места по компонентам.

## Ограничения CC, которые учитываем

- Лимит времени без yield. Решение: корутины, опция автоматических yield.
- Размер диска (обычно около 1 МБ, зависит от конфига сервера). Решение: сжатие, ленивая загрузка, минификация.
- Версия CC: часть API зависит от версии **(проверить, какие версии поддерживаем)**.
- Lua в CC (Cobalt): числа это double, нет `int`. `bit32` 32-битный.
